每个后端是一个独立的 Go module（各自拥有 go.mod/go.sum），目录结构统一分为两层：
- 根包（aliyun、charm、loki、sentry、tencent）：面向应用的可构造 Logger 适配器，导出 NewXxxLogger + options.go，并声明扩展接口（如 `type Logger interface { log.Logger; Close() error }`），实现 Debug/Info/Warn/Error/With/Enabled。
- `contract/` 子包：唯一 import 根 bconf（bootstrapv1.Logger_Backend）的位置，通过 Provider(ctx, *bootstrapv1.Logger_Backend) 按 backends[].type 分派到对应后端，返回 (log.Logger, cleanup func(), error)，保持根模块零契约依赖。

适配器内部模式一致：post 方法在构建条目时同步调用 `log.ContextAttrsToArgs(ctx)` 提取上下文属性流，之后异步发送不再持有 ctx；With 派生实例共享底层 producer/buffer，extra 字段累积追加 keyvals；云端后端（aliyun/sentry/tencent/loki）默认 Enabled 返回 true；Close 负责冲刷缓冲或关闭 SDK producer。

依赖方向单向：各适配器 require 根 `github.com/kalandramo/bald/log` 与各自的第三方 SDK（aliyun-log-go-sdk、charmbracelet/log、getsentry/sentry-go、tencentcloud-cls-sdk-go、Loki HTTP API），适配器之间互不引用。
