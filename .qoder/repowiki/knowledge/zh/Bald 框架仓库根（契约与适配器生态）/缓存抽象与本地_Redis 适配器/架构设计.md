模块按「契约 vs 适配器」切分：
- `cache/local`、`cache/redis` 为纯 SDK 适配器，不依赖 bconf；`cache/local/contract`、`cache/redis/contract` 各自 import bconf 把 `bootstrapv1.Cache` 段映射为对应 Provider（返回 `(any, func(), error)`，cleanup 由 appkit 停机 Effect 回放）。
- `cache/loadable` 是横切组合器，仅依赖 `bald/cache` 契约接口，用 `golang.org/x/sync/singleflight` 对同一 key 的并发 miss 合并为一次 LoadFunc 调用，避免缓存击穿；通过 `WithDegradeOnError` 支持缓存故障降级到 loader。
- 每个子目录均为独立 go.mod，根 module 不 require 任何适配器，适配器单向 require 根，保证依赖图可见。
- Redis 适配器在 contract 层根据配置互斥选择 cluster / sentinel / standalone 三种部署模式，并在 dial 阶段 Ping 确认连通后才交给 Provider 装配。
- 两个 contract 包都通过 `var _ baldcache.Cache = (*xxx)(nil)` 做接口守卫，并通过 `Provider` 函数形状的类型守卫确保可被 `appkit` 段驱动复用。
