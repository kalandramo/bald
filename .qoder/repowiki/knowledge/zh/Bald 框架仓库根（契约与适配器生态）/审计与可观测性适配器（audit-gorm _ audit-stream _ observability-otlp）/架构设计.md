三个并列 contrib 子模块，均遵循「contract 契约装配 + 根包纯实现」的分层模式：
- contract 子包仅 import bconf/gen/go/bootstrap/v1 与 appkit，把 bootstrapv1 配置段映射为 appkit.*Provider 构造器（NewStoreProvider/NewStreamProvider/NewTracerProvider/NewPrometheusProvider/NewOTLPProvider），由业务在 Build 内注册并覆盖 std 默认；根实现包保持零契约依赖。
- audit-gorm/store.go 实现 StoreAuditor，通过 WithRecordMapper 适配自定义表结构，WithFallback 支持双写降级；audit-stream/stream.go 通过内存缓冲 chan + 后台 goroutine XADD 到 Redis Stream，Close 时 drain 剩余事件。
- observability-otlp 拆分为 trace/ 与 metrics/ 两个独立桥接包，分别调用 go.opentelemetry.io/otel/sdk 设置全局 TracerProvider/MeterProvider；contract 统一导出 AppProviders("my-app") 一次性装配 tracer + metrics。
- 依赖方向单向：contrib → pkg/appkit、pkg/audit、observability/metricshttp；不反向依赖根 module 的业务逻辑。
- 生命周期通过 Provider 返回的 cleanup 函数经 appkit.Effect 逆序回放，确保审计尾批在指标/span flush 之后收集。
