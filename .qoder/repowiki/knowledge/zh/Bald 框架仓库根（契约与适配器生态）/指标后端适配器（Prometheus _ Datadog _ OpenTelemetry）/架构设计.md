本模块是 metrics 契约的适配器层，由三个独立的 Go module 组成（metrics/prometheus、metrics/datadog、metrics/otel），每个子目录都是自包含的 go.mod 单元，单向依赖根 module 的 `github.com/kalandramo/bald/metrics` 接口定义。

- 契约面：根 module 的 `metrics.Metrics` 接口（以及可选的 `metrics.Closer`）是唯一的内部边界；三个后端各自通过 `var _ metrics.Metrics = (*Provider)(nil)` 编译期断言实现契约。
- 适配器面：
  - prometheus：基于 `client_golang/prometheus`，支持私有 Registry 或共享 DefaultRegisterer，使用 `promauto.Factory` + `sync.Mutex` + 多张 map 缓存 Counter/Histogram/Gauge 及其 Vec 实例，并通过 `labelNames` 冻结首次出现的 label 维度以符合 Prometheus 稳定维度要求。
  - datadog：基于 `datadog-go/v5/statsd`，通过 UDP 发送 DogStatsD 报文，标签转为 `key:value` 字符串切片，GaugeAdd 复用 Count 语义，暴露 Close 以关闭连接。
  - otel：基于 `otel/sdk/metric` + OTLP exporter（gRPC 或 HTTP），使用 `sdkmetric.PeriodicReader` 周期性导出，MeterProvider 注册到全局 `otel.SetMeterProvider`，测试时可通过包内 `withReader` 注入 ManualReader。
- 构造模式统一：每个 Provider 采用 Option/config 函数式配置，`defaultConfig()` 给出默认值，`New(opts ...Option)` 应用选项后返回 `*Provider`；prometheus 额外提供 `NewWithDefaultRegistry` 作为便捷入口。
- 资源生命周期：datadog 与 otel 同时实现 `metrics.Closer`，在 Close 中 flush/close 底层客户端；prometheus 无状态、无需关闭。
