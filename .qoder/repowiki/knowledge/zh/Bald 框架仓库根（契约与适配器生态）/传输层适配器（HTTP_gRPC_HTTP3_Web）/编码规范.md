- 每个协议适配器都以独立 Go module 形式存在（各自带 go.mod/go.sum），并实现 `transport.Server` 的 `Start(ctx) error` / `Stop(ctx) error` / `Endpoint() string` 三方法契约。
- `Start` 中先构建 `tls.Config` 再创建监听器，使证书配置错误在启动期直接失败，避免占端口后回退导致 Endpoint 指向已关闭地址。
- `Endpoint()` 通过 `transport.Extract(cfg.Addr, ln)` 把通配符或 `:0` 解析为具体 hostPort，并以协议前缀（`http://` / `grpc://`）拼接返回，未监听时返回空串。
- 监听器字段 `ln` 与 `sync.RWMutex` 配对保护：`Start` 加写锁写入，`Endpoint` 先快照再解锁，避免在持锁期间执行 `net.Interfaces` 枚举。
- 业务 handler 与传输层解耦：HTTP/gRPC 适配器不注册业务路由，仅暴露 `AttachHandler` 或 `HealthServer()` 等扩展点，由上层装配层（gateway / appkit.WithHealth）完成挂载。
- Web 层的请求处理函数统一遵循「绑定 → 校验 → 执行业务 → WriteResponse」四步流水线，错误经 `berrors.BadRequest` 等标记后由 `ErrorResponse` 统一映射为 HTTP 状态码。
