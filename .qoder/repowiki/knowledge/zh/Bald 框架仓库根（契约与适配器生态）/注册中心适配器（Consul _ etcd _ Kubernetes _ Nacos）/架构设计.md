每个后端目录（consul/etcd/kubernetes/nacos）都是一个独立的 Go module（见各自 go.mod），遵循「contract 契约层 + 根包适配器层」的双层结构：
- `*/contract`：契约装配层，声明 `Type` 常量与 `Provider(ctx, cfg)` 工厂函数，负责把 `bootstrapv1.Registry` 配置段映射为本后端的 `Option` 并调用根包的 `New(opts...)`；同时通过同文件的 `AppProvider()` 暴露 `appkit.Provider`，以 `registry.<backend>` 子段作为启用开关（段存在即启用，缺失即跳过），节点 Phase=Bootstrap、Priority=PriorityRegistry、Reload=Restart、EffectName=`appkit:registrar-client`。
- 根包：纯 SDK 适配器，仅依赖本模块内部类型与第三方库，不 import bconf/appkit；对外导出 `Registrar`、`Option`、`New`、`Close`、`Watch` 等接口能力（consul/etcd/nacos 在 watcher.go 中实现服务变更监听，kubernetes 无 watcher.go 因 CRD 语义不同）。
依赖方向单向向外：根适配器 → 第三方客户端；contract 层 → 根适配器 + bconf + appkit；根包不反向依赖 contract，保证 SDK 零契约依赖。
