模块以 `appspec.json` 为单一真相源，经 `bald gen app --spec` 生成两个独立入口 `cmd/bald-demo-api` 与 `cmd/bald-demo-worker`，二者仅负责启动 `app.Execute()` 并调用 `bootstrap.Options("api"|"worker")` 装配。

内部分层：
- `greetv1/` 是领域层，暴露 `Domain` 装配值（Declare/ApplyNode/Reconcile/Services/RouteTable），通过 `appkit.Domain` 把 biz 节点挂到 `domain.greet.biz`，并把 HTTP 路由挂到 `server.http`。
- `internal/apiserver/` 持有自定义 gin 路由与中间件链（Recovery / RequestID / Logging / CORS），并通过 `exampleRoutes` 注入 `/v1/ping`、`/v1/users/:id`、`/v1/articles/:id` 等样例接口；HTTP handler 与 gRPC handler 由 `buf` + `grpc-gateway` 从 `api/proto/greet.proto` 生成至 `handler/gin` 与 `routes`。
- `internal/bootstrap/` 是装配核心：`assemble.gen.go`、`domains.gen.go`、`variants.gen.go` 由 AppSpec 生成，`providers.go`、`register_grpcgw.go`、`register_nacos.go` 提供变体接入点（`grpcgw`、`nacos`），`seed/` 注入策略与初始数据。
- `user/` 提供用户实体及 GORM/内存两种 provider 实现，作为 domain 层的数据访问示例。

依赖方向单向向下：`cmd/*` → `internal/bootstrap` → `greetv1` → `pkg/appkit`；适配器（`registry/nacos`、`transport/web`、`contrib/store-gorm`）被根模块 require，本示例仅消费其公开 API。
