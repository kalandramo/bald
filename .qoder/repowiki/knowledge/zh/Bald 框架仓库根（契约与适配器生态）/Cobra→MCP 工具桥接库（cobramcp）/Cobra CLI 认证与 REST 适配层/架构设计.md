模块由三个文件构成，职责清晰分层：
- `root.go` 仅负责组装根 `cobra.Command`，把 `startCommand`、`toolCommand`、`streamCommand`、`restCommand` 以及 `vscode`/`cursor` 两个 IDE 桥接子命令挂到同一命名空间下，是 cobra 命令树的入口。
- `auth.go` 实现两层认证组合器：外层接受用户注入的 `func(http.Handler)http.Handler`（`Config.AuthMiddleware`），内层实现静态 Bearer token 校验（`Config.AuthToken`），并通过 `publicPaths` 放行 OAuth well-known 发现端点；token 比较使用 `crypto/subtle.ConstantTimeCompare` 防时序攻击，`bearerToken` 兼容裸 token 与带 `Bearer ` 前缀两种形式，行为与 transport/sse 的 DefaultTokenExtractor 对齐。
- `rest.go` 通过 `serveREST` 自建 `http.Server`，按 `/toolName` 路由注册每个 tool 的 POST handler，将 flat JSON 请求体反序列化为 `ToolInput` 后复用 MCP 子进程执行管线（`buildCommandArgs` + `execSubprocess`），并统一以 `{error,stdout,stderr,exitCode}` 形式的 JSON 响应；OAuth Protected Resource Metadata（RFC 9728）作为公开端点直接挂载在 mux 上，不参与认证。
依赖方向：三者均只依赖 mcp-go 的 server 类型和 spf13/cobra，不反向依赖任何 transport/registry 适配器；REST 服务通过 `buildAuthMiddleware` 复用 auth.go 的中间件链，使 SSE 与 REST 两条路径共享同一份认证策略。
