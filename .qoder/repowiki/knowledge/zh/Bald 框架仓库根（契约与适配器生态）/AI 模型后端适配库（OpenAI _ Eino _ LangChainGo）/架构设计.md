三个并列的 Go module（`ai/openai`、`ai/eino`、`ai/langchaingo`），每个 module 内部按「契约 vs 适配器」切分：
- `contract/` 子包依赖根 `bconf` 生成的 `bootstrapv1.Ai`，负责把 YAML 段映射到本模块的 `Config` 并构造具体对象，对外暴露 `Type` 常量与 `Provider(ctx, *bootstrapv1.Ai) (any, func(), error)` 函数签名；
- 顶层包（`client.go`/`config.go`/`options.go` 等）是零契约依赖的纯 SDK 封装，仅依赖第三方 SDK（`go-openai`、`cloudwego/eino-ext/components/model/openai`、`tmc/langchaingo`）与本模块的 `Config`。

三者结构同构但各自独立成 module，避免引入公共包破坏「实现零契约依赖」的边界；openai 后端直接复用 `sashabaranov/go-openai`，eino 后端通过 `cloudwego/eino-ext` 包装 OpenAI 兼容 API，langchaingo 后端则基于 `tmc/langchaingo` 同时暴露 embedding/vectorstore/memory 能力。所有 module 均通过 `replace github.com/kalandramo/bald/bconf => ../../bconf` 指向仓库内的 bconf，从而保持单向依赖：适配器 → 根模块。
