三个独立 Go module（`transport/sse`、`transport/webrtc`、`transport/websocket`），每个模块通过 `go.mod` 的 `replace` 把根 `github.com/kalandramo/bald/transport` 指向父目录，从而单向依赖根包定义的 `transport.Server` 接口；三者互不引用。

- `transport/sse`：核心由 `server.go`/`stream.go`/`stream_manager.go`/`subscriber.go`/`event_log.go` 组成 SSE 事件推送栈，`contract/` 子包是契约装配层（仅 `contract.go` + 测试），负责把 `bconf/bootstrapv1.Server_Sse` 段映射为 `sse.Option` 并返回 `func(context.Context, *bootstrapv1.Server) (transport.Server, func(), error)`——该函数类型被业务侧 `server.sse` Provider 调用，避免 `transport/sse` 直接依赖 `bootstrap`，形成「契约面」与「实现面」的解耦。
- `transport/webrtc`：基于 `pion/webrtc/v4` 实现信令 HTTP 端点 + ICE/DTLS/SRTP 数据通道，内部按职责拆分为 `session.go`/`session_manager.go`（会话生命周期）、`sfu_router.go`（SFU 路由）、`signaling.go`（SDP/ICE 交换）、`message.go`（二进制 JSON 编解码）、`media_track.go`（媒体轨道），并提供 `cmd/sfu_server` 与 `cmd/test_client` 两个可执行示例。
- `transport/websocket`：最薄的一层，封装 `gorilla/websocket` 升级流程，结构体与 API 刻意对齐 webrtc 版本以便复用同一套消息注册模型。

三者的共同高层抽象：`Server` 都内嵌或组合 `http.Server`/`ServeMux`，使用 `SessionManager` 管理连接、支持 `RegisterMessageHandler` 按 `NetMessageType` 分派、提供 `Use(Middleware)` 注入标准 `http.Handler` 中间件链，并通过 `encoding.Codec` 做 payload 序列化。
