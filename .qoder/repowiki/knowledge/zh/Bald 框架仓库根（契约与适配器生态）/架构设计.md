- 根 module `github.com/kalandramo/bald` 仅暴露契约面（appkit 框架、bconf/bconfig/bootstrap、pkg/* 横切工具），不 require 任何适配器；所有 transport/registry/cache/store/log/metrics/encoding/ai/contrib 等适配器单向 require 根，形成「契约在上、实现在下」的扇入结构。
- 模块清单由 `scripts/list-modules.sh` 唯一派生：find 仓库中所有 go.mod（排除 .git 与 _example*），CI 与本地 Taskfile 均消费该脚本，避免本地与 CI 覆盖范围漂移。
- `.github/race-skip.txt` 作为 race detector 排除项的唯一真相源，每条排除必须写明上游竞争理由，bald 自身竞争不得放入。
- `.golangci.yml` 与 `.github/workflows/workflow-lint.yml` 通过 `task ci-workflow-lint` 做作业文件校验，使 lint 配置与 CI 作业保持一致。
- 适配器统一遵循「contract + provider」模式：在 bootstrapv1 段定义配置契约，adapter 子包提供 Config → 实例 的映射函数，由 appkit 的 Provider 装配层按名称注册与注入。
- `_example/bald` 是独立验证模块，不在 list-modules.sh 清单内，由 Taskfile 的 example-* 任务单独驱动，且 replace 到仓库外的 kratos 以模拟真实业务依赖。
