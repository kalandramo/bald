# bald 测试工具：e2e 复用工具的收编（P13）

> 适用包：`pkg/testkit`
> 关联文档：`架构优化路线.md`（§P13 卫生项：e2e 工具收编）
> Last updated: 2026-09-02
> Status: Accepted

## 摘要

`pkg/testkit` 收编跨项目复用的测试工具（P13 卫生项）。此前 `freeAddr` 在 `pkg/server/server_test.go`、`_example/bald`、`examples/go-bald-admin` 等处各自复制，收编于此供新 e2e 直接 import——「验证类代码保留」原则（架构优化路线 §P13）的落地：测试基础设施与测试用例分离，不塞进核心包。

## 设计

### 当前 API

```go
// FreeAddr 分配一个当前空闲的 TCP 端口，返回 "127.0.0.1:port"。
func FreeAddr(tb testing.TB) string
```

### 使用场景与关键坑

**用途**：「先拿地址、再启动监听」的 e2e 场景。典型坑是 `GatewayServer` 的后端 gRPC 地址**不能用 `:0`**（转码转发时无从得知真实端口），必须用确定端口。

**实现**：监听 `:0` 拿到内核分配的端口后立刻关闭，再用该端口。两次调用间端口可能被抢占，不是 100% 可靠，但对测试足够，且比硬编码端口安全得多。

**带 `127.0.0.1` 是刻意的**：裸 `:port` 会被 gRPC 客户端解析成 `[::1]:port`（IPv6），与监听在 IPv4 的服务不匹配，导致 `connection refused`。

## 理由与取舍

**决策①：为什么独立 `pkg/testkit` 而不是塞进各包的 `_test.go`？** 跨包/跨 module（`_example`、`examples`、`tests`）复用需要导出；塞进核心包会污染生产 API 面。独立测试工具包把"测试基础设施"与"业务代码"分开，且符合 P13 的"验证类代码保留"原则。

**决策②：为什么只有一个函数？** 工具按需收编——反复出现且与业务无关的测试辅助（端口分配、gRPC bootstrap 等）才进 `pkg/testkit`，避免变成测试代码的垃圾场。当前仅 `FreeAddr` 是真实复现多处的。

## 兼容性

纯增量：新增 `pkg/testkit` 包；原各处的内联 `freeAddr` 改为转发调用，行为不变。
