# bald 校验：按请求类型名分发的 Validate 方法约定 + 规则式轻量校验

> 适用包：`pkg/validation`
> 关联文档：`路由注册与绑定设计.md`（先 Bind 后一次 Validate 的 web 流水线）、`Bald 配置系统设计.md` §2（字段级规则走 proto `buf.validate` 注解）
> 参考实现：onexstack `pkg/validation`（按类型名分发约定，移植并修复静默失效问题）
> Last updated: 2026-09-02
> Status: Accepted

## 摘要

`pkg/validation` 提供基于反射的「按请求类型名分发」校验能力：业务为每个请求类型 `XxxRequest` 实现一个方法 `ValidateXxxRequest(ctx, *XxxRequest) error`，注册进 `Validator`；每次请求进入时 `Validator.Validate(ctx, req)` 自动按类型名找到对应方法执行。**本包只负责"分发"，不负责"规则表达"**——声明式的字段级规则应写在 proto 的 `buf.validate` 注解里（protovalidate 运行时读取）；本包适合承载注解表达不了的复杂校验（查库、权限比对、跨字段动态逻辑）。

## 设计

### 1. 按类型名分发（`Validator`）

```go
type Validator struct { /* validators map[类型名]→校验函数 */ }

func NewValidator(validators any) (*Validator, error)  // 传 nil = 无校验器（合法）
func (v *Validator) Register(validators any) error      // 注册 obj 上全部 Validate* 方法
func (v *Validator) Validate(ctx context.Context, request any) error // 按类型名分发；未注册放行
func RequestTypeName(request any) string                // 请求类型名（去指针）
```

**约定**：方法名 = `Validate` + 请求类型名，签名 = `func(recv T, ctx context.Context, req *XxxRequest) error`。

**关键行为（P2 修复）：只要方法名以 `Validate` 开头，就被视为"声明了校验意图"，此时任何一项约定不满足都返回 error，而不是静默跳过。** 这是为防止方法名拼写错误（如 `ValidateUserRequst`）导致校验完全不生效且无任何提示——这类静默失效在生产环境等同于"没有校验"。

### 2. 规则式轻量校验（无类型分发时的单字段检查）

```go
// ValidRequired：必填字段非空。fields 为「字段名 = 值」键值对；返回首个缺失字段错误。
func ValidRequired(fields map[string]any) error

// ValidRange：数值/字符串长度区间检查（int/int64/float64/string）。
func ValidRange(field string, value any, min, max any) error

// ValidPattern：前缀/后缀/包含/长度规则。rules 形如 "prefix:abc"、"len:min,max"。
func ValidPattern(field, value string, rules ...string) error
```

与 `Validator` 互补，二者都返回 `error`（建议封装为 `pkg/berrors` 的语义错误）。

### 3. 与 web 流水线的衔接

`pkg/web` 的多源绑定（body/query/path）完成后，在 handler 内一次调用 `validator.Validate(ctx, req)`——「先 Bind 后一次性 Validate」。约定避免了一层抽象（不用把校验注册成 map），类型名即注册键，声明即注册。

## 理由与取舍

**决策①：为什么用"方法名约定"而非"map 注册"？** 方法名约定零样板：实现 `ValidateXxxRequest` 即自动注册，没有"忘了 Register 就校验失效"的中间态；且类型名唯一，天然避免 key 拼写不一致。代价是约束了方法命名与签名——`Register` 的严格校验兜底保证拼错立即报错。

**决策②：为什么字段级规则不放进本包？** 声明式字段规则（必填/范围/格式）用 proto `buf.validate` 注解表达更贴合 proto-first：schema 即校验，客户端/文档共享同一份规则。本包只承接注解表达不了的命令式校验。分界清晰，避免两套字段规则表达并存。

**决策③：为什么未注册的请求放行而非拒绝？** 校验是增量能力：新请求类型未写校验方法时，放行让业务先跑起来（fail-open），由测试/代码评审补校验。这与 `Register` 的严格意图声明（一旦写了 Validate* 就不得静默失效）互补——"写了的必须正确，没写的先放行"。

## 兼容性

纯增量：新增 `pkg/validation` 包，`pkg/web` 绑定流水线新增可选项（未注入 Validator 时跳过校验），无破坏。

## 实现与过渡

| 步骤 | 内容 | 验证 |
|---|---|---|
| 1 | `Validator` 按类型名分发 + `Register` 严格意图校验 | 单测：正确注册、签名不符报错、拼错方法名报错、未注册放行 |
| 2 | `ValidRequired`/`ValidRange`/`ValidPattern` | 单测：各类型边界、空值、规则组合 |
| 3 | `pkg/web` 接入 `Validate` 步骤 | e2e：go-bald-admin 绑定后校验 |
