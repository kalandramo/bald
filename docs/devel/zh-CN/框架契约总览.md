# 框架契约总览（API Surface）

> 本文档是 `bald` 框架**所有公开契约**的速查表：导出接口、类型、函数、常量及其签名。
> 目的不是替代各设计文档，而是让使用者一眼看清「能用什么、签名是什么、怎么接入」。
> 所有包路径前缀为 `github.com/kalandramo/bald/pkg/`。
>
> 设计主线（详见各设计文档）：**核心零后端耦合**，注册中心 / 配置中心 / 校验 / 追踪等
> 可选能力均通过「最小接口 + 桥接适配器」注入，核心不绑定任何具体实现。

---

## 0. 模块与依赖层级

```
appkit        ← 编排层（组合 server/registry/config/log，最上层）
 ├─ server      服务端抽象（HTTP/gRPC/Gateway）
 ├─ registry    服务注册抽象 + FromKratos 桥接
 ├─ config      配置加载器 + RemoteSource 抽象 + FromKratosSource 桥接
 ├─ conf        框架配置 Protobuf 契约（默认值/校验/flag 绑定）
 ├─ web         gin HTTP 处理流水线（Handler/Validator/响应）
 ├─ middleware  gin / grpc 中间件（依赖倒置接口 + 实现）
 ├─ berrors     传输中立错误模型（核心包零依赖）
 │    ├─ grpcerr  gRPC 边界转换（可选）
 │    └─ httperr  HTTP 边界转换（可选）
 ├─ log         结构化日志（Logger/Options/kvs/Context）
 ├─ validation  命令式校验分发器（依赖倒置）
 └─ contextx    请求上下文键（trace_id / user / vars）
```

## 1. `pkg/appkit` — 应用编排

| 符号 | 签名 | 说明 |
|---|---|---|
| `AppKit` | `type AppKit struct`（非导出字段） | 应用编排器；提供 `Run(ctx)` / `Viper()` / `Config()` / `Logger()` / `Endpoints()` / `Scheme()` |
| `New` | `func(bootstrap *confv1.Bootstrap, opts ...Option) (*AppKit, error)` | 构造；`bootstrap` 来自 `conf.NewBootstrap()`；`opts` 见下 |
| `(*AppKit).Run` | `func(ctx context.Context) error` | 启动所有 server + 注册 + 优雅停机；内部有 CAS 防重入 |
| `(*AppKit).Viper` | `func() *viper.Viper` | 返回合并后的 viper 实例（BeforeStart 内 `Unmarshal` 用） |
| `(*AppKit).Config` | `func() *confv1.Bootstrap` | 返回已加载的配置 |
| `(*AppKit).Logger` | `func() *log.Logger` | 返回日志句柄 |
| `(*AppKit).Endpoints` | `func() []server.Endpoint` | 返回各 server 的监听端点（供注册中心用） |
| `(*AppKit).WaitReady` | `func(ctx, timeout) error` | 等待所有 server 就绪（探针/readyz 用） |

**函数式选项 `Option = func(*AppKit)`：**

| 选项 | 签名 | 说明 |
|---|---|---|
| `ID` / `Name` / `Version` | `func(string) Option` | 应用元信息 |
| `Registrar` | `func(r registry.Registrar) Option` | 注入 bald 注册中心 |
| `KratosRegistrar` | `func(r kratosregistry.Registrar) Option` | 桥接 kratos 注册中心（= `Registrar(registry.FromKratos(r))`） |
| `RemoteConfig` | `func(src config.RemoteSource) Option` | 注入远程配置源 |
| `ConfigFile` | `func(f string) Option` | 指定 `--config` 路径 |
| `Env` | `func(env string) Option` | 运行环境（影响默认文件名 / 远程 path） |
| `WatchConfigFile` | `func(watch bool) Option` | 本地文件热更新 |
| `OnConfigChange` | `func(fn func(*viper.Viper)) Option` | 配置变更回调 |
| `Servers` | `func(servers ...server.Server) Option` | 注入 server 列表 |
| `StopTimeout` | `func(d time.Duration) Option` | 优雅停机超时 |
| `BeforeStart` / `AfterStart` / `BeforeStop` / `AfterStop` | `func(fn func(context.Context) error) Option` | 生命周期钩子 |
| `Bind` | `func(prefix string, opt any) Option` | 注册业务配置 flag；`opt` 为 `proto.Message`（conf.BindFlags）或 `PlainBinder`（AddFlags，prefix 必须为空） |
| `PlainBinder` | `interface { AddFlags(fs *pflag.FlagSet) }` | 无前缀 flag 注册器（如 `log.Options` 内部注册 `--log.*`） |

> 关键约束：`Bind("http", &bootstrap.Http)` 的 prefix 与 viper 键（`http.addr`）、
> 环境变量（`NAME_HTTP_ADDR`）、文件键四者一致，flag 才能压过文件/远程。
> 构造后不要再自行 `AddFlags(pflag.CommandLine)`，否则重复注册。

## 2. `pkg/server` — 服务端抽象

| 符号 | 签名 | 说明 |
|---|---|---|
| `Server` | `interface { Run(ctx) error; Stop(ctx) error; Endpoint() (Endpoint, error); Scheme() string }` | server 统一接口 |
| `Endpoint` | `type Endpoint struct { Address string; Scheme string }` | 监听端点（注册中心消费） |
| `EndpointFunc` | `type EndpointFunc func() (Endpoint, error)` | 端点惰性获取（避免构造期锁死地址） |
| `ServiceEndpoint` | `type ServiceEndpoint struct { Key string; Value Endpoint }` | 注册中心用的 key/value |
| `NewFromProto` | `func(bs *confv1.Bootstrap, opts ...ServerOption) (*ServerX, error)` | 从 proto 配置批量构造 HTTP/gRPC/Gateway server 集合 |
| `ServerOption` | `type ServerOption func(*ServerOptions)` | server 构造选项 |
| `NewGRPCServerWithRegister` | `func(cfg *confv1.Grpc, register GRPCRegister, opts ...ServerOption) (*GRPCServer, error)` | gRPC server；`register` 注入 proto 服务 |
| `NewHTTPServer` | `func(cfg *confv1.Http, opts ...ServerOption) (*HTTPServer, error)` | HTTP(server) server |
| `NewGatewayServer` | `func(http *confv1.Http, grpcBackend *confv1.Grpc, register GatewayRegister, opts ...ServerOption) (*GatewayServer, error)` | grpc-gateway 反向代理；延迟解析后端地址 |
| `(*GRPCServer).Endpoint` | 实时读 `s.cfg.GetAddr()` | **不缓存**构造期快照（env 覆盖后才写回） |
| `(*GatewayServer).Start` | 延迟建 `conn` + `attachHandler`，持锁完成即释放再 `Serve` | 防与 `Stop` 死锁 |

> `GRPCRegister` / `GatewayRegister` 由调用方注入（依赖倒置）；核心不依赖具体的 proto 服务生成代码。

## 6. `pkg/web` — gin HTTP 处理流水线

| 符号 | 签名 | 说明 |
|---|---|---|
| `Handler[T, R]` | `type func(ctx context.Context, req *T) (R, error)` | 业务处理函数 |
| `Validator[T]` | `type func(ctx context.Context, req *T) error` | 请求校验器（返回 `*berrors.Error`） |
| `Defaulter` | `interface { Default() }` | 绑定后填充默认值（可选实现） |
| `HandleJSONRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 JSON body 绑定 |
| `HandleQueryRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 query 参数绑定 |
| `HandleUriRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 path 参数绑定 |
| `HandleAllRequest` | `func(c, Handler[T,R], ...Validator[T])` | URI→Query→JSON 依次绑定（JSON 覆盖，最后 Default） |
| `ShouldBindAll` | `func(c *gin.Context, obj any) error` | 多源绑定 + Defaulter 钩子 |
| `WriteResponse[T]` | `func(c *gin.Context, data T, err error)` | 统一成功/错误响应（data 为 nil 仅 200 无 body） |
| `ErrorResponse` | `func(c *gin.Context, err error)` | 写 `{error:{code,message}}`，code 取 `berrors.Error.Reason` |
| `ErrorBody` / `ErrorDetail` | `struct { Error ErrorDetail }` / `struct { Code, Message string }` | 错误响应体 |

> 校验错误用 `errors.BadRequest(...)` 等，被 `ErrorResponse` 自然映射为 HTTP 400。

## 7. `pkg/berrors` — 传输中立错误模型（核心零依赖）

| 符号 | 签名 | 说明 |
|---|---|---|
| `Error` | `struct { Code uint32; Reason string; Message string; Details map[string]string; cause error; stack []uintptr }` | 业务错误；字段级不可变 |
| `New` | `func(code uint32, reason string) *Error` | 构造 |
| `(*Error).Error` | 实现 `error` 接口 | 格式 `code: N, reason: X; cause: ...` |
| `(*Error).Is` | 按 `Reason` 匹配（忽略 Code/Message/cause） | 标准库 `errors.Is` 兼容 |
| `(*Error).WithMessage` | `func(format string, args ...any) *Error` | 注入用户文案 |
| `(*Error).WithDetails` | `func(map[string]string) *Error` | 注入 i18n 变量 |
| `(*Error).WithCause` | `func(error) *Error` | 包装底层错误 |
| `(*Error).WithCode` | `func(uint32) *Error` | 覆盖传输类别（逃生舱） |
| `(*Error).StackTrace` | `func() string` | 调用栈格式化 |
| `Is` / `As` / `Unwrap` / `Join` | 桥接标准库 | 重导出（注意 `New` 因签名冲突不重导出） |
| `FromError` | `func(err error) (*Error, bool)` | 从 error 链提取 `*Error` |
| 错误码常量 | `CodeOK=0 … CodeUnauthenticated=16`（与 gRPC codes 1:1） | 不要改数值 |
| 便捷工厂 | `BadRequest/NotFound/AlreadyExists/PermissionDenied/ResourceExhausted/FailedPrecondition/Unauthenticated/Internal/Unimplemented/Unavailable/DeadlineExceeded(reason) *Error` | 一行构造 |

### 7.1 `pkg/berrors/grpcerr`（gRPC 边界，可选 import）

| 符号 | 签名 | 说明 |
|---|---|---|
| `ToStatus` | `func(err error) *status.Status` | `*Error` → gRPC status + `errdetails.ErrorInfo`；未命中退回 Unknown |
| `FromStatus` | `func(st *status.Status) error` | status → `*Error`（还原 Reason/Details） |

### 7.2 `pkg/berrors/httperr`（HTTP 边界，可选 import，仅标准库）

| 符号 | 签名 | 说明 |
|---|---|---|
| `CodeToHTTP` | `func(code uint32) int` | Code → HTTP 状态（未知兜底 500） |
| `HTTPToCode` | `func(httpStatus int) uint32` | 反向映射（多对一取最贴切，未知兜底 Unknown） |
| `StatusCode` | `func(e *berrors.Error) int` | `= CodeToHTTP(e.Code)`（替代原核心包 `Error.StatusCode()` 以免循环依赖） |

> 全局函数（`log.Context` / `log.Error` / ...）消费 ctx 中 `ContextWithAttrs` 注入的属性，实现 trace_id 贯穿。

## 12. 契约接入速记

| 能力 | 核心抽象 | 桥接/实现 |
|---|---|---|
| 服务注册 | `registry.Registrar` | `registry.FromKratos(...)` / `inmemory.New()` |
| 配置中心 | `config.RemoteSource` | `config.FromKratosSource(...)` |
| 请求校验 | `web.Validator[T]` / `validation.Validator` | 业务实现 |
| 错误模型 | `berrors.Error` | 边界 `grpcerr` / `httperr` |
| 可观察性 | OTel no-op tracer | 注入 TracerProvider + `log.WithOTelHandler` |
| 数据访问 | `store.Store[T]` + `DBProvider[T]` | `store/inmemory` 内存实现；`bald-store-gorm` 等独立子模块经 `DBProvider` 桥接 |
| 配置契约 | `confv1.*`（proto） | `conf.NewBootstrap` / `Validate` / `BindFlags` |

> 全部契约遵循「核心定最小接口，实现由调用方注入」；新增后端（如 nacos）只需提供
> 实现并接 `FromKratos` / `FromKratosSource`，不改核心代码。
