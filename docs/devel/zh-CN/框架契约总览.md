# 框架契约总览（API Surface）

> 本文档是 `bald` 框架**所有公开契约**的速查表：导出接口、类型、函数、常量及其签名。
> 目的不是替代各设计文档，而是让使用者一眼看清「能用什么、签名是什么、怎么接入」。
> 主模块包前缀为 `github.com/kalandramo/bald/pkg/`；`bconf` / `bconfig` / `bootstrap` /
> `transport` / `log` / `berrors` 均为独立 Go module（依赖全景见《模块依赖关系.md》）。
>
> 设计主线（详见各设计文档）：**核心零后端耦合**，注册中心 / 配置中心 / 校验 / 追踪等
> 可选能力均通过「最小接口 + 桥接适配器」注入，核心不绑定任何具体实现。

## 0. 模块与依赖层级

> 顶层模块（独立 Go module：bconf/bconfig/bootstrap/transport/log/berrors）之间的
> 依赖方向、启动数据流与设计原则见《模块依赖关系.md》；下图为 API 视角的包层级。

```
appkit        ← 编排层（组合 transport/registry/bootstrap/config/log + 能力解析/组件/效应账本/挂载，最上层）
 ├─ transport   独立 module：Server 契约（HTTP/gRPC/Gateway）+ 子包 grpcserver/httpserver/gateway/web
 ├─ registry    服务注册抽象 + FromKratos 桥接
 ├─ bootstrap/config  独立 module bootstrap 内：配置装载器 Store（Layer/RemoteSource/FromKratosSource 桥接）
 ├─ bconf       独立 module：框架配置 Protobuf 契约 bootstrapv1（默认值/校验/flag 绑定）
 ├─ transport/web     gin HTTP 处理流水线（Handler/Validator/响应）
 ├─ middleware  gin / grpc 中间件（依赖倒置接口 + 实现）
 │    └─ bundle   横切关注点门面（双传输链序固化，P10）
 ├─ berrors     独立 module：传输中立错误模型（包名 errors，惯例别名 berrors）
 │    ├─ grpcerr  gRPC 边界转换（可选）
 │    └─ httperr  HTTP 边界转换（可选）
 ├─ log         独立 module：结构化日志（Logger/Options/kvs/Context；实现子包 log/slog）
 ├─ authn       认证抽象（Authenticator/AuthClaims/ctx 注取）
 ├─ authz       授权抽象（Authorizer + P9 传输中立归一化）
 ├─ audit       审计抽象（Auditor/AuditEvent/全局注入点）
 ├─ metrics     指标抽象（Recorder/Event，otel API 封装）
 ├─ validation  命令式校验分发器（依赖倒置）
 ├─ store       泛型数据访问层（零引擎依赖 + 多租户）
 ├─ testkit     测试工具（FreeAddr 等）
 └─ contextx    请求上下文键（user_id / username / trace_id / request_id / tenant_id）

contrib/       独立 module 桥接（module 前缀 github.com/kalandramo/，单向依赖核心，按需引入）：
  bald-authn-jwt / bald-store-gorm / bald-cache-redis /
  bald-authz-casbin / bald-observability-otlp
```

## 1. `pkg/appkit` — 应用编排

| 符号 | 签名 | 说明 |
|---|---|---|
| `AppKit` | `type AppKit struct`（字段非导出） | 应用编排器：`New(opts...)` 构造、`Run(ctx)` 启动；对外方法见下 |
| `New` | `func(opts ...Option) *AppKit` | 构造（不返回 error；配置经 Run 的 loadConfig 加载） |
| `(*AppKit).Run` | `func(ctx context.Context) error` | 启动所有 server + 注册 + 优雅停机；CAS 防重入（重复调用返回 `ErrAlreadyRunning`） |
| `(*AppKit).Settings` | `func() map[string]any` | 合并后的配置快照（深拷贝；BeforeStart 内 `Unmarshal` 用；Run 前/未加载为 nil） |
| `(*AppKit).Config` | `func() *config.Store` | 配置仓库（`GetString/GetStringSlice/Unmarshal` 实时点路径读取；Run 前/未加载为 nil） |
| `(*AppKit).Done` | `func() <-chan struct{}` | Run 结束（含停机完成）后关闭；供测试/嵌入等待 |
| `(*AppKit).Err` | `func() error` | Run 的退出错误（Run 返回后有效） |
| `(*AppKit).Resolve` | `func() error` | S1 能力声明校验（Run 启动早期自动调用；缺失聚合报错） |
| `(*AppKit).UndoEffects` | `func(parent context.Context)` | T1 效应账本立即逆序回放并清空（幂等；e2e `t.Cleanup` 隔离用；Run 停机自动调用） |
| `(*AppKit).MountComponent` | `func(ctx, Component) error` | A1 运行期挂载：Start + 纳入停机序列 + mount 审计；`ErrNotRunning`/已销毁拒绝 |
| `(*AppKit).UnmountComponent` | `func(ctx, name string) error` | A1 运行期卸载：移除 + 立即 Dispose（LIFO）+ unmount 审计 |
| `(*AppKit).ListComponents` | `func() []string` | 当前停机序列中的组件名（启动/挂载序，观测用） |
| `(*AppKit).ReconcileNow` | `func(ctx context.Context)` | 立即执行一次全量协调（按注册序；测试/手动触发） |
| `ErrAlreadyRunning` | `var error` | 重复调用 `Run` 的哨兵错误 |

**停机五阶段（stopAll）**：0 效应账本逆序回放 → 1 BeforeStop → 2 Server.Stop 并发 → 3 AfterStop → 4 组件逆序 Dispose（装配期 + 运行期挂载统一处理；`disposed` 闭环拒绝迟挂载）。

**函数式选项 `Option = func(*AppKit)`：**

| 选项 | 签名 | 说明 |
|---|---|---|
| `ID` / `Name` / `Version` | `func(string) Option` | 应用元信息 |
| `Registrar` | `func(r registry.Registrar) Option` | 注入 bald 注册中心 |
| `KratosRegistrar` | `func(r kratosregistry.Registrar) Option` | 桥接 kratos 注册中心（= `Registrar(registry.FromKratos(r))`） |
| `RemoteConfig` | `func(src config.RemoteSource) Option` | 注入远程配置源（bootstrap/config 的 kratos 桥） |
| `ConfigLayers` | `func(ls ...config.Layer) Option` | 契约层直通 Store（`Registry.Build` 产出，注册序=优先级；2026-09-05 归一接入） |
| `ConfigFile` | `func(f string) Option` | 指定 `--config` 路径 |
| `Env` | `func(env string) Option` | 运行环境（影响默认文件名 / 远程 path） |
| `WatchConfigFile` | `func(watch bool) Option` | 本地文件热更新 |
| `OnConfigChange` | `func(fn func(map[string]any)) Option` | 配置变更回调（形参为重合并后的新快照） |
| `Servers` | `func(servers ...transport.Server) Option` | 注入 server 列表 |
| `StopTimeout` | `func(d time.Duration) Option` | 优雅停机超时 |
| `BeforeStopTimeout` / `AfterStopTimeout` | `func(d time.Duration) Option` | Before/AfterStop 钩子独立超时（默认同钩子超时，避免单钩子阻塞拖垮整机停机） |
| `BeforeStart` / `AfterStart` / `BeforeStop` / `AfterStop` | `func(fn func(context.Context) error) Option` | 生命周期钩子 |
| `Bind` | `func(prefix string, opt any) Option` | 注册业务配置 flag；`opt` 为 `proto.Message`（bconf.BindFlags）或 `PlainBinder`（AddFlags，prefix 必须为空） |
| `PlainBinder` | `interface { AddFlags(fs *pflag.FlagSet) }` | 无前缀 flag 注册器（如 `log.Options` 内部注册 `--log.*`） |
| `Effect` | `func(name string, undo func(context.Context) error) Option` | T1 效应账本：登记全局写入的逆操作（停机阶段 0 逆序回放；panic 隔离、独立超时） |
| `EffectTimeout` | `func(d time.Duration) Option` | 单条 undo 的独立超时（默认同钩子超时） |
| `Provides` | `func(caps ...string) Option` | S1 声明进程提供的能力（重复声明报错） |
| `Requires` | `func(component string, caps ...string) Option` | S1 声明组件依赖的能力（缺失 fail-fast；重复幂等） |
| `Components` | `func(comps ...Component) Option` | C1 注册进程内组件（顺序 Start、停机逆序 Dispose） |
| `ComponentTimeout` | `func(d time.Duration) Option` | 组件 Start/Dispose 独立超时 |
| `OnKeyChange` | `func(key string, fn func(old, new string)) Option` | R1 key 级配置订阅：仅当该 key 值确实变化才触发；与 `OnConfigChange` 共存（先全量后分发）；基线=首次加载值 |
| `Auditor` | `func(a audit.Auditor) Option` | D4：注入 appkit 自身审计后端（A1 重组审计、R1-2 协调审计）——与业务 `bundle.Audit` 注入同源，消除 split-brain sink；未注入回退全局 `audit.GetAuditor()`（`resolveAuditor` 单一解析序：注入→全局→nop 默认） |
| `Reconcile` | `func(name string, fn func(ctx context.Context, rctx *ReconcileCtx) error) Option` | R1-2 期望态协调：声明以 `name`（配置键）为标识的协调器；框架在**启动收敛期**（`loadConfig` 基线后、AfterStart 前）与**每次配置变更**（keywatch 分发后）自动调用 `fn`；语义对齐 K8s controller 的 diff-apply（期望态写在配置，框架只更新有变动部分） |
| `DiffStrings` | `func(want, have []string) (add, remove []string)` | R1-2 导出工具：期望/实际集合 diff，返回需新增/移除项；供协调函数做幂等 diff-apply（期望==实际直接早退，不抖动） |


**`Component` 接口（C1）**：`interface { Name() string; Start(ctx) error; Dispose(ctx) error }`——进程内基础设施（trace provider/metrics exporter/审计后端连接等）。`ComponentFunc(name, dispose)` 适配纯清理函数。`transport.Server` = Component + Endpoint。

**`Registry[T]` 泛型注册表**：`NewRegistry[T]()` / `Register(name, impl) error`（装配期，重名报错不覆盖）/ `MustRegister(name, impl)`（重名 panic，init() 自注册用）/ `Get(name) (T, bool)` / `Mount(name, impl) (undo func(), err error)`（A1 运行期可逆挂载，undo 幂等）/ `Unmount(name) (T, bool)` / `List() []string`（升序）。框架预置三类注册点：`ServerRegistry` / `MiddlewareRegistry` / `ProviderRegistry`（后两者存 `any`，调用方断言）；`RegisterStoreProvider(name, factory any)` 供桥接子模块 register 包 init() 自注册（如 `bald-store-gorm/register`）。

**`ReconcileCtx`（R1-2）**：协调函数入参，携带 `Settings map[string]any`（协调开始时的配置快照，只读）+ 辅助读取 `String(key) string` / `StringSlice(key) []string`（点路径）、`Name string`（协调器名）、`app *AppKit`，并暴露实际态查询/操作原语：`Mounted() []string`（已挂载组件名列表）/ `Has(name string) bool` / `Mount(ctx, name, c Component) error` / `Unmount(ctx, name string) error`（基于 A1 的 `Registry.Mount/Unmount` 与 `AppKit.MountComponent/UnmountComponent`）。方法是并发安全的（`reconMu` 保护 `reconItems`）。协调器内部应自行用 `DiffStrings` 比对期望态（`rctx.StringSlice(key)` 等）与这些方法返回的实际态，再调用 `Mount/Unmount` 收敛；部分失败留中间态，下一次协调补全（controller 自愈）。

**R1-2 协调上下文与测试装置**：`NewReconcileCtx(app *AppKit, name string, settings map[string]any) *ReconcileCtx` 构造协调上下文（供测试或「手动触发协调」；正常路径由 `runReconcilers` 内部构造）。`NewHarness() *AppKit` 构造测试装置——跳过配置加载与 server 启动、直接进入运行态（`MountComponent`/`ReconcileCtx.Mount` 可用），供跨 module 集成测试驱动协调逻辑（examples/*、tests/* 是独立 Go module，无法用 `export_test.go` 暴露未导出成员的惯用法）；生产代码用 `New` + `Run`，不使用装置。

> 关键约束：`Bind("http", &bootstrapv1.Server_Http{...})`（契约实例）的 prefix 与配置键（`http.addr`）、
> 环境变量（`NAME_HTTP_ADDR`）、文件键四者一致，flag 才能压过文件/远程。
> 构造后不要再自行 `AddFlags(pflag.CommandLine)`，否则重复注册。

## 2. `transport` — 服务端抽象（module `github.com/kalandramo/bald/transport`）

> 顶层契约在包 `transport`；构造函数分布在子包：
> `transport/http`（包名 `httpserver`）、`transport/grpc`（包名 `grpcserver`）、
> `transport/gateway`（包名 `gateway`）。下表符号归属：除标注外，顶层契约在 `transport`，
> `NewHTTPServer`/探针常量在 `httpserver`，`NewGRPCServer*` 在 `grpcserver`，`NewGatewayServer` 在 `gateway`。

| 符号 | 签名 | 说明 |
|---|---|---|
| `Server` | `interface { Start(ctx context.Context) error; Stop(ctx context.Context) error; Endpoint() string }` | 统一生命周期契约（与 kratos transport.Server 兼容的超集）；Endpoint 支持 `:0` 动态端口解析 |
| `ReadinessFunc` | `func(ctx context.Context) error` | 就绪探针回调；nil 视为恒就绪 |
| `Ready` | `func(fns ...ReadinessFunc) ReadinessFunc` | 多依赖就绪聚合（`errors.Join` 保留全部失败） |
| `DefaultHealthPath` / `DefaultReadyPath` | `const "/healthz"` / `const "/readyz"`（`httpserver`） | HTTP 探针默认路径 |
| `NewHTTPServer` | `func(cfg *bootstrapv1.Server_Http, handler http.Handler, readiness ReadinessFunc, opts ...HTTPServerOption) *HTTPServer` | HTTP(S) server；业务 handler 挂 "/"，框架探针自动注册（业务同名路径优先） |
| `HTTPServerOption` / `WithProbePaths(health, ready)` | `type HTTPServerOption func(*HTTPServer)` | 覆盖探针路径（默认 `/healthz` `/readyz`） |
| `NewGRPCServer` | `func(cfg *bootstrapv1.Server_Grpc, srv *grpc.Server, readiness ReadinessFunc, opts ...GRPCServerOption) *GRPCServer` | 包装已构建 `*grpc.Server`（不含 health/reflection，业务自注册） |
| `NewGRPCServerWithRegister` | `func(cfg *bootstrapv1.Server_Grpc, unary []grpc.ServerOption, register func(s *grpc.Server), readiness ReadinessFunc, opts ...GRPCServerOption) *GRPCServer` | gRPC server + health/reflection 自动注册 + 业务 service |
| `GRPCServerOption` / `WithReadinessPollInterval(d)` | `type GRPCServerOption func(*GRPCServer)` | 覆盖 readiness 后台轮询间隔（默认 2s，`defaultReadinessPollInterval`） |
| `NewGatewayServer` | `func(httpCfg *bootstrapv1.Server_Http, backend *bootstrapv1.Server_Grpc, register func(ctx context.Context, conn *grpc.ClientConn) (http.Handler, error), readiness ReadinessFunc) (*GatewayServer, error)` | grpc-gateway 反向代理；延迟建 conn + 持锁时序防 Stop 死锁 |
| `(*GRPCServer).Endpoint` / `(*HTTPServer).Endpoint` | 实时读 cfg 地址 + listener | 支持 `:0` 动态端口、可达 IP 解析 |

> 就绪语义：HTTP `/readyz` 与 gRPC health（`SetServingStatus("")`，整体服务）共用同一 `ReadinessFunc`，两端对称（P1）。业务 handler 由调用方注入（`http.Handler` / `register` 回调），核心不依赖具体 proto 生成代码。

## 3. `pkg/registry` — 服务注册

| 符号 | 签名 | 说明 |
|---|---|---|
| `Registrar` | `interface { Register(ctx context.Context, ins *ServiceInstance) error; Deregister(ctx context.Context, ins *ServiceInstance) error }` | 注册中心最小契约 |
| `ServiceInstance` | `struct { ID, Name, Version string; Metadata map[string]string; Endpoints []string; Kind string }` | 注册实例：ID=实例唯一标识（appkit 默认 hostname-随机后缀，同机多实例不冲突）；Endpoints=各 `Server.Endpoint()` 解析地址（支持 `:0`）；Kind=single/multi |
| `FromKratos` | `func(r kratosregistry.Registrar) Registrar` | kratos → bald 桥接（etcd/consul/nacos 即插即用） |
| `inmemory.New` | `func() *inmemory.Registrar` | 内存实现（开发/测试；`Register` 按 ID 覆盖） |
| `(*inmemory.Registrar).List` | `func() []*ServiceInstance` | 已注册实例快照（测试断言用） |

> 后端（etcd/consul/nacos）经 `FromKratos` 接入，核心不绑定。`Discovery`（GetService 发现抽象）当前未提供，属远期（agent-native / 集群）。

## 4. `bootstrap/config` — 配置装载器（`github.com/kalandramo/bald/bootstrap/config`，2026-09-05 收编自独立 module `bald/config`；同日 viper 退役、Registry 归一为层模型）

> 统一层模型内核：`Layer`（命名源层：远程桥/契约源/本地文件都是层）+ env/flag 枚举 +
> map 深合并（copy-on-write），类型规范化下沉 §5 `bconf.UnmarshalMap`。
> 优先级（高 → 低）flag > env > 本地文件 > 契约源层（`Layers` 列表首最高）> 远程桥（基准）；
> 任一层热更新均触发**全量重合并**，各层缓存保留（本地覆盖不污染远程基准、远程更新不冲掉本地覆盖）。
> 2026-09-05 起 viper 已退役（其全部能力由内核替代，且 AllSettings 不含纯 env key），
> 格式收敛为 yaml/json（`Layer.Format` 为空回退 yaml，yaml.v3 兼容 JSON）；
> `bootstrap.Registry.Build` 产出 `[]Layer`（注册序=层优先级），装配主链路不再经过
> `bconfig.FallbackReader`（退守同 key 多候选回退域，见配置系统设计 §3.6）。

| 符号 | 签名 | 说明 |
|---|---|---|
| `Layer` | `struct{Name string; Reader bconfig.Reader; Format string; Watch bool}` | 命名配置源层（整文档源，key 固定传空串；`Watch=true` 且 reader 实现 `bconfig.ValueWatcher` 才参与热更新） |
| `Options` / `Load` / `RemoteSource` / `FromKratosSource` | 同前 | 层模型合并 + 热更新 + kratos 桥接（`Remote` 内部适配为最低基准层） |
| `Store` | `Load` 返回 | 配置仓库：`Settings() map[string]any`（深拷贝快照）、`Get/GetString/GetStringSlice`（点路径）、`Unmarshal(msg)`、`Close()`（停层 watch 与自建源；reader 资源归 Registry cleanup） |
| `Unmarshal` | `func(m map[string]any, msg proto.Message) error` | 配置快照 → proto（委托 `bconf.UnmarshalMap(m, msg)`） |

## 5. `bconf` — 契约层工具（`github.com/kalandramo/bald/bconf`，2026-09-05 自 pkg/conf 迁入并切 bootstrapv1）

| 符号 | 签名 | 说明 |
|---|---|---|
| `NewBootstrap` | `func() *bootstrapv1.BootstrapConfig` | 手写默认值（App.Id=主机名/Http :8080/Grpc :9090/Logger slog） |
| `Validate` | `func(cfg *bootstrapv1.BootstrapConfig) error` | app/server.addr/logger 段校验，启动前 fail-fast |
| `BindFlags` | `func(fs *pflag.FlagSet, msg proto.Message, prefix string)` | 遍历 proto 描述符注册带前缀 flag；**nil 子消息跳过**（防实例化破坏「非 nil 即启用」语义，如 Server_TLS） |
| `UnmarshalMap` | `func(m map[string]any, msg proto.Message) error` | 配置树 → proto（类型规范化 + 合并式语义 + repeated 替换）；加载器无关 |

> 契约类型 `bootstrapv1.BootstrapConfig / Server_Http / Server_Grpc / Logger` 等由
> `bconf/proto/` buf managed mode 生成到 `bconf/gen/go/`，transport/bootstrap 全部直连。
> legacy `confv1` 契约与 `pkg/conf`、`api/proto`（含 protoc-gen-defaults stub）已于 2026-09-05 删除；
> 服务器地址语义为「指针直通」：flag/Unmarshal 合并与 server Start 读值同一对象，无桥接快照。
> `LogOptions`（契约 Logger → slogadapter.Options）归装配层 bootstrap（见 §11.6）。

## 6. `transport/web` — gin HTTP 处理流水线（`github.com/kalandramo/bald/transport/web`，包名 `web`，2026-09-05 自 pkg/web 迁入）

| 符号 | 签名 | 说明 |
|---|---|---|
| `Handler[T, R]` | `type func(ctx context.Context, req *T) (R, error)` | 业务处理函数 |
| `Validator[T]` | `type func(ctx context.Context, req *T) error` | 请求校验器（返回 `*berrors.Error`） |
| `Defaulter` | `interface { Default() }` | 绑定后填充默认值（可选实现） |
| `HandleJSONRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 JSON body 绑定 |
| `HandleQueryRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 query 参数绑定 |
| `HandleUriRequest` | `func(c, Handler[T,R], ...Validator[T])` | 仅 path 参数绑定 |

| 横切组装 | `middleware/bundle` | `bundle.New(...)` 双传输链序固化（P10） |
| 装配校验 | `appkit.Provides/Requires` | `Resolve()` 启动期 fail-fast（S1） |
| 拆卸正确性 | `appkit.Effect` / `Component` / `Registry.Mount` | 停机逆序回放/Dispose；e2e 隔离用 `UndoEffects`（T1/C1/A1） |
| 配置细粒度热更新 | `appkit.OnKeyChange` | key 级 diff 触发，与 `OnConfigChange` 共存（R1） |

> 全部契约遵循「核心定最小接口，实现由调用方注入」；新增后端（如 nacos）只需提供
> 实现并接 `FromKratos` / `FromKratosSource`，不改核心代码。
