## §0 总体定位

bald 是**融合三方设计精华**的 Go 服务框架（`README.md:1-7`）：

| 来源 | 吸收的要点 |
|---|---|
| **onexstack/pkg/app** | 启动期 Options + 配置理念（`--config` 由调用方注入） |
| **Kratos** | `transport.Server` 契约与 `registry.Registrar` 接口形态（注册后端 2026-09-06 起改直连 SDK provider） |
| **go-lulu（`wind`）** | 自研 App 层精髓——errgroup 并发启停、优雅停机防坑、崩溃级联停止、Run 防重入、可观察通道、`Endpoint()` 动态端口注册 |

**第一轮（P0–P9）的主题**：把「进程能正确启停」做扎实——生命周期编排正确性、
契约/实现分离、错误与观测统一、多租户与安全抽象。

### §0.5 认证与授权的空白（P7 前置）

> `认证与授权抽象设计.md:4` 引用「`架构演进路线.md`（§0.5 / P7）」，`:17` 引用「P7（架构演进路线 §0.5）落地前」。

**空白状态**：P7 落地前，bald 只有 `pkg/middleware` 的**校验/可观测拦截器**接口，
**认证**（谁在调）与**授权**（能不能调）尚无统一抽象——`_example` 无法演示登录/认证/权限拦截。

**这是 P7 的出发点**：必须先固化「认证/授权」两个正交抽象的位置与边界，才能谈中间件接线。

**语义（可核实，`berrors/errors_test.go:67`）**：「P3：构造即捕获调用栈，`StackTrace()` 返回非空字符串且含调用方帧」。

## §P7 认证与授权抽象

**语义（可核实）**：
- `认证与授权抽象设计.md:4,17`：P7 = `pkg/authn`（认证抽象）+ `pkg/authz`（授权抽象）双接口；
- `contrib/authz-casbin/casbin.go:4`：「对齐 bald P7/P9 原则」。

**设计**：
- `pkg/authn`：`Authenticator` / `AuthClaims` / ctx 注取（零引擎耦合）；
- `pkg/authz`：`Authorizer` 接口（`Authorize(ctx, subject, object, action)`），
  桥接子模块外置（`contrib/authz-casbin`），核心不 import casbin；
- **判定与执行分离**：核心只定义接口，策略引擎由业务注入。

详见《[认证与授权抽象设计](./认证与授权抽象设计.md)》。

## §P8 多租户

**语义（可核实）**：
- `框架契约总览.md` §11.5：「多租户（**P8**）：`RegisterTenant(key, valueFunc)` 注册隔离维度」；
- `框架契约总览.md` §12：`bald-store-gorm` 标注「**P8/M6**」。

**设计**：
- `store.RegisterTenant(key, valueFunc)` 注册隔离维度（重复注册覆盖）+ `DefaultTenantFunc` 从 `contextx.TenantID` 取值；
- **读路径**：`mergeTenant` 注入租户等值条件（下沉 DAL 自动注入，避免漏写导致跨租户泄漏）；
- **写路径**：`injectWriteTenant` 无条件覆写租户列（闭环隔离）；
- **平台级豁免**：`WithPlatformLevel` 显式声明（fail-closed：默认隔离生效）。
- **逆操作**：`store.UnregisterTenant`（T1 效应账本对偶成员，第二轮补齐）。

详见《[Bald 存储设计](./Bald%20存储设计.md)》。

## §P9 传输中立归一化

**语义（可核实）**：
- `Bald 中间件设计.md:171`：「**P9 的核心收益**——根治 REST/gRPC 双命名空间 RBAC——不应依赖调用方记得 opt-in」；
- `contrib/authz-casbin/casbin.go:7`：「传输中立归一化已由核心拦截器完成（**P9 反哺**）」；
- `bconf/gen/go/bald/appspec/v1/appspec.pb.go:44`：「是否启用归一化中间件链（**P9** + P10 bundle Normalized()）」。

**设计**：`pkg/authz/normalize.go` 提供传输中立归一化——
- `DefaultGRPCObject` / `DefaultGRPCAction`（FullMethod → 资源名/动作）；
- `DefaultHTTPObject` / `DefaultHTTPAction`（path/method → 资源名/动作）；
- **一次性根治**：REST 与 gRPC 共用同一策略空间（同一资源在两面得到同一 object/action）；
- **默认开启**：`bundle.Normalized()` 默认启用，`Raw()` 显式 opt-out 回 P7 原始语义
  （安全相关的默认值选择：默认正确优于默认兼容）。

**关键分工**：桥接（casbin）只做**纯 Enforce**，归一化在**核心拦截器层**完成——
勿在桥接重复，那是双命名空间的根源。
