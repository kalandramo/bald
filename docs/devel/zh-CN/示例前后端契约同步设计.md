# 示例前后端契约同步设计（buf 按消费者扇出）

> 状态：方案定稿，待落地（示例项目独立前实施第一步）。
> 适用范围：`examples/go-bald-admin`（后端）+ `examples/go-bald-admin-web`（前端），
> 参考范式：go-wind-admin `backend/api/buf.*.gen.yaml`。

## 1. 问题：契约双写

当前前后端契约存在两份手写真相源：

- 后端：proto（`api/<域>/v1/*.proto`，**已带全 `google.api.http` annotation**——
  每个 RPC 声明 REST method/path/body，REST 契约的真相源已在 proto 里）。
- 前端：手写 API 层（`src/common/apis/` 9 文件约 425 行：URL/method/请求响应类型）
  + 手写类型（`@@/types/api`）。

双写的代价已有实锤：2026-09-08 的 writePB 命名事件——后端 protojson 输出
snake_case，前端 types 按 camelCase 建模（默认假设），字段静默错位、页面空数据。
任何 URL 变更、字段增删，前端都靠人肉同步。

## 2. 决策：buf v2 按消费者扇出 + 生成物跨目录直出

照 go-wind-admin 的配置形态，proto 单一真相源、按消费方一个 gen 配置、互不污染：

```
examples/go-bald-admin/api/
├── buf.yaml                        # 模块定义（已有）
├── buf.gen.yaml                    # Go 面（go/go-grpc/grpc-gateway，已有；随迁 v2）
├── buf.web.typescript.gen.yaml     # 【新增】前端 TS 客户端
│                                   #   out: ../../go-bald-admin-web/src/api/generated/
└── buf.openapi.gen.yaml            # 【第二步，可选】OpenAPI v3 文档
                                    #   out: <backend>/assets，嵌入服务供 Swagger/Apifox
```

要点（抄 go-wind-admin 的部分）：

- **`version: v2` + `inputs.paths` 收窄输入**：前端/OpenAPI 面只吃本示例的 proto，
  不吃依赖模块。
- **`clean: true`**（TS/OpenAPI 面）：proto 删消息后旧生成物不残留。Go 面照旧。
- **`managed.disable` 列出 BSR 依赖模块**（googleapis 等）：不改写第三方 go_package
  （现有 buf.gen.yaml 的 except 语义在 v2 的迁移形态，落地时按 buf v2 语法转换）。
- **跨目录直出**：生成物直接落前端 `src/api/generated/`——契约同步靠重新生成，
  不靠人肉。

消灭的东西：9 个手写 apis 文件 + 手写 types（生成替换后删除，顺带清掉该目录的
GBK 乱码注释——2026-09-08 编码修复未覆盖到这批文件，不必再修）。

## 3. 不能盲抄的差异点

go-wind-admin 与 bald 示例的三处硬差异，照抄会翻车：

1. **响应形状（已决策 2026-09-10，见《错误模型设计》决策⑧）**：成功体 = 裸
   protojson（`UseProtoNames: true`，snake_case，无信封）；错误体 = google.rpc.Status
   JSON（`{"code", "message", "details":[{reason, metadata}]}` + 真实 HTTP 状态码），
   与 grpc-gateway 转码输出字节级同形。**不采用** go-wind-admin 的 Kratos
   `{code, data, message}` 信封（一切 200）：它破坏 proto3 JSON 契约、要求 REST
   双实现定制 error handler、丢失 HTTP 语义（401→logout 等既有逻辑失效）、
   `httperr` Code↔HTTP 映射表失效。对 TS 生成是简化：响应类型 = proto message
   原生直出，无信封解包层。
2. **transport 封装保留**：前端现有 `@/http/axios`（token 注入、错误处理、
   响应拦截）不替换——生成物替换的是 URL/method/类型定义，request 封装仍走
   axios.ts。选型插件时验证它允许自定义 transport（tx7do
   `protoc-gen-typescript-http` 或同等物，落地前以真实生成物验证为准）。
3. **无 Kratos errors 默认响应**：OpenAPI 面 `default_response=false` 照抄
   go-wind-admin 的选型即可（bald 错误模型是 berrors，不是 google.rpc.Status
   转码）。

## 4. 独立迁移形态约束（前置决策）

示例项目将来独立出 bald 仓库时，**前后端必须合成一个 monorepo**
（go-wind-admin 形态：`backend/` + `frontend/` 同仓）。理由：跨目录直出
（`api/ → frontend/src/api/generated/`）只在同仓内持续成立；拆两个仓库这条
链路就断了，只能走 CI 同步或发包，复杂度翻倍且必然漂移。

独立动作（届时）：`go-bald-admin` → `backend/`、`go-bald-admin-web` →
`frontend/`（或同级），gen 配置里的相对 out 路径随之调整，其余不变。

## 5. 落地步骤

| 步骤 | 内容 | 验收 |
|---|---|---|
| 第一步（独立迁移前做） | buf v1→v2 迁移（Go 面行为不变）+ 新增 `buf.web.typescript.gen.yaml`，生成物落前端，替换手写 apis/types；配套错误体改造（决策⑧落地：`writeBizErr` 改 google.rpc.Status JSON 形状并提升为框架契约，axios 错误分支统一读 `message` + `details[0].reason`、删 `errorData?.error` 双 key hack） | 前端 `vue-tsc` 编译过 + 页面联调回归（登录/用户/租户/菜单/字典各走一通，含一通错误路径）+ 手写层删除 |
| 第二步（可选，按需） | 新增 `buf.openapi.gen.yaml`（OpenAPI v3，`naming=json`/`enum_type=string`/`output_mode=merged`/`default_response=false`） | openapi.yaml 嵌入后端 assets，Swagger UI/Apifox 可消费 |

插件选型风险：TS 插件（tx7do 系）的响应形状与 bald 裸 protojson 的匹配度、
snake_case 字段名选项，落地第一步时以真实生成物逐项验证；不匹配则换插件或加
薄适配层，**不为迁就插件改后端契约**。

## 6. 决策记录

| # | 决策 | 理由 |
|---|---|---|
| 1 | proto 单一真相源，前后端契约一律生成 | 消灭双写；writePB 事件已证人肉同步必漂移 |
| 2 | 按消费者扇出 gen 配置（Go/TS/OpenAPI 各一份） | 互不污染，go-wind-admin 同款且经生产验证 |
| 3 | transport 封装（axios.ts）保留，只替换 URL/method/类型 | 生成物不管 token/错误处理/拦截器 |
| 4 | 独立时前后端合 monorepo | 跨目录直出只在同仓成立 |
| 5 | TS 插件选型以真实生成物验证，不为插件改后端契约 | 契约优先，工具适配契约而非相反 |
| 6 | OpenAPI 面二步走、按需做 | 当前无文档面消费方，YAGNI |
| 7 | 响应形状：成功裸 protojson + 错误 google.rpc.Status JSON | 三面（gRPC/gateway/gin）一份契约；Kratos 信封被否决（决策⑧详证） |
