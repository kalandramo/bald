# pkg/registry 设计文档

> 服务注册/发现抽象层。定义 bald 框架与具体注册中心（etcd / consul / nacos / kubernetes / ...）
> 之间的最小契约，使业务代码不感知底层实现；具体后端以**直连 SDK 的 provider**
> 形式放 `contrib/registry/<backend>`（独立 module，依赖隔离），契约装配走
> **显式注册表**（不用 init + blank import）。
>
> 2026-09-06 起：kratos 桥接路线（`kratos.go` / `appkit.KratosRegistrar`）已删除，
> 抽象面对齐 go-wind（Registrar + Discovery + Watcher），provider 移植自
> go-wind-plugins/registry。

---

## 1. 背景与设计目标

bald 作为轻量框架，需要一个服务注册/发现能力，但**不应强制绑定任何具体注册中心**。

| 目标 | 说明 |
| --- | --- |
| 最小契约 | `Registrar`（注册）+ `Discovery`（发现）+ `Watcher`（变更监听），零依赖。 |
| 可插拔后端 | 内存实现用于开发/测试；直连 SDK provider 按需 import，依赖隔离。 |
| 契约装配 | `bootstrapv1.Registry` 段声明后端与连接参数，代码只显式注册 provider。 |
| 显式注册 | main() 里逐个 `MustRegister`，未 import 的后端零依赖零编译成本、运行期 fail-fast。 |
| 优雅停机 | 停机时优先 `Deregister`，避免流量打到已停止的实例；client 生命周期由停机 Effect 回放。 |

## 2. 整体架构

```
┌────────────────────────────┐
│           main()           │
│  rr := appkit.NewRegistrarRegistry()
│  rr.MustRegister("nacos", nacoscontract.Provider)
│  appkit.FromBootstrap(cfg, appkit.WithRegistrarRegistry(rr))
└──────────────┬─────────────┘
               │ 显式注册 provider（注册序即依赖图）
               ▼
┌────────────────────────────┐   RegistrarRegistry.Build(ctx, cfg.GetRegistry())
│        pkg/appkit          │   按契约 registry.type 单选分发（fail-fast）
│  FromBootstrap 阶段 B 构造  │──────────────┐
│  appkit 生命周期驱动注册     │              ▼
└──────────────┬─────────────┘   ┌───────────────────────────────────┐
               │ Registrar 接口  │         pkg/registry（契约层）      │
               ▼                 │  ServiceInstance / Registrar      │
┌────────────────────────────┐   │  / Discovery / Watcher            │
│  contrib/registry/<backend>│   └───────────────────────────────────┘
│  （直连 SDK，独立 module）   │
│  etcd / nacos / consul /   │   纯 SDK 实现，零契约依赖
│  kubernetes                │   （contract 子包才 import bconf）
│  + contract 子包（契约映射） │
└────────────────────────────┘
```

- `pkg/registry` 只定义**契约**，自身不包含任何后端实现细节。
- `contrib/registry/<backend>` 是直连 SDK 的独立 module（复制 go-wind 实现）：
  根包纯 SDK 实现（零契约依赖），`contract` 子包做 `bootstrapv1.Registry` 段 →
  options 映射并导出 Provider。
- `appkit` 拥有**注册生命周期**（start 后 Register、stopAll 前 Deregister、
  Effect 回放释放 client）——这是 go-wind RegistryAction（实例被 `_ = reg` 丢弃）
  缺失的一环，bald 的 builder 必须返回实例。

## 3. 核心类型

### 3.1 ServiceInstance

```go
type ServiceInstance struct {
    ID        string            // 实例唯一 ID（如 hostname+uuid）
    Name      string            // 服务名（逻辑名，如 "bald-demo"）
    Version   string            // 服务版本
    Metadata  map[string]string // 附加元数据（scheme、region 等）
    Endpoints []string          // 实际可访问地址（来自 Server.Endpoint()，支持 :0 动态端口）
    Kind      string            // 实例类型（"single" / "mixed"）
}
```

字段约束：

- `Endpoints` 由 `appkit.buildInstance()` 聚合各 `Server.Endpoint()` 得到。
- 动态端口（`:0`）场景下，注册前由 `appkit.waitForEndpoints()` 轮询等待真实端口解析，
  避免把未绑定地址注册出去。
- **可达性保证**：`Endpoint()` 经由 `pkg/server.Extract` 生成，通配符/空 host
  （如 `:8080`、`:0`）会被替换为本机首个全局单播 IP，显式 IP 原样保留；
  且未监听时返回空字符串，杜绝注册通配符地址（如 `0.0.0.0:port`）。
- `Kind` 由 server 数量推导：`len(servers)==1` 为 `"single"`，否则 `"mixed"`。
- JSON 序列化是 go-wind `wind.Instance` 的超集（多 `kind` 字段），后端数据互通。

### 3.2 Registrar / Discovery / Watcher 接口

```go
type Registrar interface {
    Register(ctx context.Context, instance *ServiceInstance) error
    Deregister(ctx context.Context, instance *ServiceInstance) error
}

type Discovery interface {
    GetService(ctx context.Context, name string) ([]*ServiceInstance, error)
    Watch(ctx context.Context, name string) (Watcher, error)
}

type Watcher interface {
    Next(ctx context.Context) ([]*ServiceInstance, error)
    Stop() error
}
```

- `Registrar` 满足服务注册语义；`Discovery`/`Watcher` 面向客户端服务发现
  （对齐 go-wind 抽象面，provider 已实现，bald 侧消费方出现即可用）。
- `Deregister` 用于优雅停机，实现应保证幂等。

## 4. 实现一：内存版（inmemory）

`pkg/registry/inmemory/inmemory.go` 提供线程安全的内存实现，**不依赖任何外部组件**，
适用于单实例开发、测试与本地调试。行为要点：

- 以 `instance.ID` 为索引；同 ID 重复 `Register` 会**覆盖**而非新增。
- `Deregister` 对不存在的 ID 安全返回（幂等）。
- 全程 `sync.RWMutex` 保护；`List()` 是调试/测试扩展方法，不属于接口。
- **已知边界**：传入 `nil` 实例会 panic（调用方 appkit 保证不传 nil，行为已文档化）。

## 5. 实现二：contrib/registry 直连 provider（etcd / nacos / consul / kubernetes）

### 5.1 布局与依赖隔离

每个后端是独立 module（对齐 contrib/authn-jwt 先例，go-wind 同款隔离）：

```
contrib/registry/etcd/
├── go.mod                    # module github.com/kalandramo/bald-registry-etcd
├── registry.go               # Registry：Register/Deregister/GetService/Watch
├── watcher.go  service.go  errors.go  options.go
└── contract/contract.go      # 契约映射：bootstrapv1.Registry → options + Provider
```

- 根包**零契约依赖**（只有 SDK + bald 契约层）；只有 `contract` 子包 import
  bconf（protobuf-only，轻）。import 未用的后端 → 零依赖零编译成本。
- 双模式构造（对齐 bconfig provider 约定）：
  - `New(opts...)`：按 options **自建 SDK client 并拥有其生命周期**（Close 关闭）——契约装配路径；
  - `NewWithClient(c, opts...)`：**注入**既有 client，不负责关闭——复用路径
    （应用内已有连接可共享，也便于测试注入桩）。
- 实现移植自 go-wind-plugins/registry（etcd：lease 心跳 + 断链指数退避重试；
  nacos：SDK v2 直连，ephemeral 实例；consul：TTL 心跳 + 健康检查；kubernetes：
  pod label/annotation 原位发现，参考实现）。

### 5.2 契约装配：RegistrarRegistry（显式注册）

`pkg/appkit/registrar.go`（放 appkit 是因为 Provider 签名引用主模块
`pkg/registry.Registrar`；放 bootstrap module 会形成 bald⇄bald/bootstrap 模块循环）：

```go
type RegistrarProvider func(ctx context.Context, cfg *bootstrapv1.Registry) (registry.Registrar, func(), error)

type RegistrarRegistry struct{ /* providers map[string]RegistrarProvider */ }

func NewRegistrarRegistry() *RegistrarRegistry
func (r *RegistrarRegistry) MustRegister(typ string, p RegistrarProvider)  // 重名/空名/nil fail-fast
func (r *RegistrarRegistry) Build(ctx context.Context, cfg *bootstrapv1.Registry) (registry.Registrar, func(), error)
```

与 config Registry（`bootstrap.Registry`）的两点差异：

1. **按契约 `registry.type` 单选分发**（type 字段的契约语义就是单选）——不做
   optional 子消息迭代多选（go-wind resolveRegistry 的做法：多注册中心 fan-out
   无消费方，语义空洞）。
2. **Provider 必须返回实例**（而非仅 cleanup）——真正的 Register/Deregister
   生命周期由 appkit 驱动；cleanup 只负责 client 生命周期。

### 5.3 与 FromBootstrap 的集成

```go
rr := appkit.NewRegistrarRegistry()
rr.MustRegister("nacos", nacoscontract.Provider)
app, err := appkit.FromBootstrap(cfg, appkit.WithRegistrarRegistry(rr), ...)
```

FromBootstrap 内部（阶段 B，契约装载校验后）：

1. 显式 `WithRegistrar(r)` 实例非 nil → **优先，跳过契约装配**；
2. 契约 `registry` 段为 nil → no-op（无注册中心）；
3. 段存在但未接 `WithRegistrarRegistry` → **fail-fast**（配置意图无法兑现）；
4. 段存在 → `Build(ctx, cfg.GetRegistry())` 按 type 分发 → 注入 registrar +
   登记停机 Effect（`appkit:registrar-client`）释放 client。

时序保证：`Deregister` 先于 stopAll，Effect 回放发生在 stopAll 内——
先反注册再关 client，顺序安全。**registry 段不支持热更新**（client 重建侵入性大，
变更需重启生效）。

nacos 完整示例（build tag `nacos`）：[`_example/bald/register_nacos.go`](../../../_example/bald/register_nacos.go)
+ [`configs/bald-demo.yaml` registry 段](../../../_example/bald/configs/bald-demo.yaml)。

## 6. 生命周期（appkit 驱动）

| 阶段 | 动作 |
| --- | --- |
| 启动就绪后注册 | `Run` 等待所有 server 监听就绪（`waitForEndpoints`，`:0` 解析真实端口）→ `Register(ctx, buildInstance())` |
| 构建实例 | `buildInstance()` 聚合 `Endpoints`、推导 `Kind`、填充 `ID/Name/Version/Metadata` |
| 优雅停机先注销 | shutdown 路径优先 `Deregister`，避免流量打到正在停止的实例 |
| Effect 回放 | 停机时释放契约装配的 client（`RegistrarRegistry` cleanup；显式注入实例的 client 由业务自理） |
| 无注册中心 | `registrar == nil` 时全部安全跳过，不影响纯本地运行 |

## 7. 设计取舍

| 决策 | 理由 |
| --- | --- |
| 直连 SDK provider 取代 kratos 桥接 | 少一层间接（kratos contrib 的 nacos 还存在 SDK v1/v2 分裂坑）；provider 复制自 go-wind 现成实现，维护成本可控。 |
| 抽象面收下 Discovery/Watcher | 对齐 go-wind；接口零成本，provider 已实现，client-side LB 需求出现即可用。 |
| 每后端独立 module | SDK 重（etcd/client-go/nacos 互不相干），import 一个不拉全家。 |
| 显式注册（MustRegister） | 依赖图全程可见；未 import 的后端零编译成本，type 未注册运行期 fail-fast，不做 init 魔法。 |
| Registry 必须返回实例 | go-wind RegistryAction `_ = reg` 丢弃实例、无注册生命周期——bald 的 builder 修正此缺陷。 |
| inmemory 保留 | 开发/测试零依赖（go-wind 没有是它的短板）。 |
| registry 段不支持热更新 | client 重建侵入性大，重启生效；热更新限 logger 等无连接语义段。 |

## 9. 扩展指南

新增一个注册中心后端（如 zookeeper/polaris/eureka，契约段已预留）：

1. 建 `contrib/registry/<backend>` 独立 module：根包实现 `Registrar`（建议连同
   `Discovery`），双模式 `New(opts...)` / `NewWithClient(...)` + `Close`。
2. 写 `contract/contract.go`：契约段 → options 映射 + `Provider`，
   `const Type = "<backend>"`。
3. 业务 main()：`rr.MustRegister(<backend>contract.Type, <backend>contract.Provider)`。

仅注册（不发现）的最小后端也可直接实现 `registry.Registrar` 后
`appkit.WithRegistrar(impl)` 注入，跳过契约装配。
