# pkg/registry 设计文档

> 服务注册中心抽象层。定义 bald 框架与具体注册中心（etcd / consul / nacos / ...）之间的
> 最小契约，使业务代码不感知底层实现，并兼容 go-kratos 生态。

---

## 1. 背景与设计目标

bald 作为轻量框架，需要一个服务注册/发现能力，但**不应强制绑定任何具体注册中心**。

设计对齐 go-lulu 的去耦思路，目标如下：

| 目标 | 说明 |
| --- | --- |
| 最小契约 | `Registrar` 接口仅 `Register` / `Deregister` 两个方法，零依赖。 |
| 可插拔后端 | 内存实现用于开发/测试；kratos 后端（etcd/consul/nacos）即插即用。 |
| 生态兼容 | 通过适配器桥接 go-kratos 的 `registry.Registrar`，复用其成熟后端。 |
| 优雅停机 | 停机时优先 `Deregister`，避免流量打到已停止的实例。 |

---

## 2. 整体架构

```
┌──────────────┐    Registrar 接口    ┌──────────────────────────┐
│   appkit     │ ───────────────────▶ │      registry 包          │
│  (AppKit)    │                      │  ServiceInstance /        │
└──────────────┘                      │  Registrar 接口           │
       │                              └────────────┬─────────────┘
       │ buildInstance()                          │ 实现可替换
       ▼                                           ├──────────────┐
┌──────────────┐                          ┌────────┴─────┐  ┌──────┴─────────┐
│ ServiceInstance│ ◀──── 适配转换 ─────── │ inmemory     │  │ kratos.go      │
│  (value)       │                        │ (内存实现)    │  │ FromKratos 适配 │
└──────────────┘                          └──────────────┘  └──────┬─────────┘
                                                                   │ 桥接
                                                           ┌───────▼────────┐
                                                           │ kratos registry │
                                                           │ (etcd/consul/   │
                                                           │  nacos ...)     │
                                                           └────────────────┘
```

- `registry` 包只定义**契约**（`ServiceInstance` + `Registrar`），自身不包含任何后端实现细节。
- `inmemory` 与 `kratos.go` 是契约的两个独立实现来源，互不影响。
- `appkit` 只依赖 `registry.Registrar`，通过 `appkit.Registrar(...)` / `appkit.KratosRegistrar(...)` 注入。

## 3. 核心类型

### 3.1 ServiceInstance

`registry/service.go`（`registry.go`）定义实例模型：

```go
type ServiceInstance struct {
    ID        string            // 实例唯一 ID（如 hostname+uuid）
    Name      string            // 服务名（逻辑名，如 "bald-demo"）
    Version   string            // 服务版本
    Metadata  map[string]string // 附加元数据（scheme、region 等）
    Endpoints []string          // 实际可访问地址（来自 Server.Endpoint()，支持 :0 动态端口）
    Kind      string            // 实例类型（"single" / "mixed"）
}
```

字段约束：

- `Endpoints` 由 `appkit.buildInstance()` 聚合各 `Server.Endpoint()` 得到。
- 动态端口（`:0`）场景下，地址在监听绑定前为 `scheme://:0`；注册前由
  `appkit.waitForEndpoints()` 轮询等待真实端口解析，避免把未绑定地址注册出去。
- **可达性保证**：`Endpoint()` 经由 `pkg/server.Extract` 生成，通配符/空 host（如 `:8080`、`:0`）
  会被替换为本机首个全局单播 IP，显式 IP 原样保留；且未监听时返回空字符串，
  使 `waitForEndpoints` 正确等待 `Start` 真正执行，杜绝注册通配符地址（如 `0.0.0.0:port`）。
- `Kind` 由 server 数量推导：`len(servers)==1` 为 `"single"`，否则 `"mixed"`。

### 3.2 Registrar 接口

```go
type Registrar interface {
    Register(ctx context.Context, instance *ServiceInstance) error
    Deregister(ctx context.Context, instance *ServiceInstance) error
}
```

- 仅两个方法，满足绝大多数注册中心语义。
- `Deregister` 用于优雅停机，调用方应保证幂等（多次注销同一实例不应报错）。

## 4. 实现一：内存版（inmemory）

`pkg/registry/inmemory/inmemory.go` 提供线程安全的内存实现，**不依赖任何外部组件**，
适用于单实例开发、测试与本地调试。

```go
type Registrar struct {
    mu        sync.RWMutex
    instances map[string]*registry.ServiceInstance // key = instance.ID
}

func New() *Registrar
func (r *Registrar) Register(ctx, instance) error     // 按 ID 覆盖
func (r *Registrar) Deregister(ctx, instance) error   // 按 ID 删除（幂等）
func (r *Registrar) List() []*registry.ServiceInstance // 调试/测试用
```

行为要点：

- 以 `instance.ID` 为索引；同 ID 重复 `Register` 会**覆盖**而非新增（见 `TestRegistrar_RegisterOverwritesByID`）。
- `Deregister` 对不存在的 ID 安全返回（幂等，`TestRegistrar_Deregister` 验证了缺失实例）。
- 全程 `sync.RWMutex` 保护，`-race` 下并发注册/注销无数据竞争（`TestRegistrar_ConcurrentAccess`）。
- `List()` 是额外扩展方法，不属于 `Registrar` 接口，仅供调试与测试使用。
- **已知边界**：传入 `nil` 实例会 panic（map 赋值 nil key）。调用方（appkit）保证不传 nil，
  该行为在测试中已文档化（`TestRegistrar_RegisterNilInstance`），不在实现层额外防御以保持简洁。

## 5. 实现二：kratos 桥接（kratos.go）

`pkg/registry/kratos.go` 通过适配器模式，将 go-kratos 的 `registry.Registrar`
桥接为 bald 的 `Registrar`，从而复用 kratos 生态中成熟的 etcd / consul / nacos 后端。

```go
// FromKratos 将 kratos 的 registry.Registrar 桥接为 bald 的 Registrar。
func FromKratos(r kratosregistry.Registrar) Registrar {
    return &kratosAdapter{inner: r}
}
```

适配器只做**结构转换**，不引入额外状态：

```go
func toKratos(in *ServiceInstance) *kratosregistry.ServiceInstance {
    return &kratosregistry.ServiceInstance{
        ID:        in.ID,
        Name:      in.Name,
        Version:   in.Version,
        Metadata:  in.Metadata,
        Endpoints: in.Endpoints,
    }
}
```

- 字段逐项映射；bald 的 `Kind` 字段在 kratos 模型中无对应字段，故不传递（语义已隐含于 Metadata）。
- 该桥接使 `appkit.KratosRegistrar(...)` 可直接接受 kratos 后端构造出的 `Registrar`。

## 6. 与 appkit 的集成

`pkg/appkit` 是 `registry.Registrar` 的主要消费者，集成关系如下：

| appkit 入口 | 作用 |
| --- | --- |
| `appkit.Registrar(reg registry.Registrar)` | 注入任意 `registry.Registrar` 实现（如 `inmemory.New()`）。 |
| `appkit.KratosRegistrar(r kratosRegistry.Registrar)` | 注入 kratos 后端，内部调用 `registry.FromKratos(r)`。 |

生命周期中的注册/注销流程：

1. **启动就绪后注册**：`AppKit.Run` 等待所有 server 监听就绪（`waitForEndpoints`，
   确保 `:0` 已解析为真实端口），再调用 `register()` → `Registrar.Register(ctx, buildInstance())`。
2. **构建实例**：`buildInstance()` 聚合各 `Server.Endpoint()` 为 `Endpoints`，
   推导 `Kind`，填充 `ID/Name/Version/Metadata`。
3. **优雅停机先注销**：`AppKit` 在 shutdown 路径中优先调用 `deregister()` →
   `Registrar.Deregister(...)`，避免客户端流量打到正在停止的实例。
4. **无注册中心时安全跳过**：`registrar == nil` 时 `register` / `deregister` 直接返回，
   不影响纯本地运行。

> 典型用法（来自 `doc.go`）：

```go
reg := inmemory.New()
app := appkit.New(appkit.Registrar(reg), appkit.Servers(grpcSrv, httpSrv))
app.Run(ctx)
```

## 7. 设计取舍

| 决策 | 理由 |
| --- | --- |
| 仅 `Register` / `Deregister` 两方法 | 保持最小契约，第三方后端只需实现两个方法即可接入。 |
| 不内置 etcd/consul 实现 | 避免框架强依赖重客户端；通过 kratos 桥接复用生态，依赖在用户侧按需引入。 |
| `inmemory` 单独成包 | 开发/测试零依赖，且不影响生产构建体积。 |
| 适配器而非接口改造 | 不改 kratos 类型，仅做单向结构映射，降低耦合与维护成本。 |
| `List()` 仅内存实现提供 | 通用注册中心查询语义差异大，不纳入接口；调试能力留给具体实现。 |
| 不在 inmemory 防御 nil | 保持实现简洁，nil 防护责任交由调用方（appkit 已保证）。 |

## 8. 测试覆盖

`inmemory/inmemory_test.go`：

- `TestRegistrar_RegisterAndList`：注册后可通过 List 查到，按 ID 索引。
- `TestRegistrar_RegisterOverwritesByID`：同 ID 覆盖语义。
- `TestRegistrar_Deregister`：注销生效且对缺失实例幂等。
- `TestRegistrar_ConcurrentAccess`：50 协程并发注册/注销，需 `-race` 验证无竞争。
- `TestRegistrar_RegisterNilInstance`：文档化 nil 实例的 panic 边界行为。

`appkit/appkit_test.go`：

- `TestRegistry_RegisterDeregister`：验证 `AppKit` 启动调 `Register`、停机调 `Deregister`。

## 9. 扩展指南

新增一个注册中心后端（例如自研 gRPC 发现服务）：

1. 实现 `registry.Registrar` 接口（`Register` / `Deregister`）。
2. 在 `AppKit` 中通过 `appkit.Registrar(yourImpl)` 注入即可，无需改动框架。

若后端已在 kratos 生态中有 `registry.Registrar` 实现，直接 `appkit.KratosRegistrar(r)` 复用，
无需新增适配器。
