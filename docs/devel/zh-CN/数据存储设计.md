# 数据存储设计

> 设计目标：在 bald 框架内定义**数据访问层（DAL）的契约与可选抽象**，使业务能以统一姿态接入
> 任意存储引擎，同时保持**核心零后端耦合**（与 `registry` / `config` 同一哲学）。
>
> 本文对比两个参考实现的取舍，给出 bald 的适配方案与核心契约。
> 状态：✅ 核心契约骨架（`pkg/store`）与桥接子模块 `bald-store-gorm` 均已落地（见 §8）；本文为已实现设计的决策记录。

---

## 1. 两个参考项目的定位差异

| 项目 | 定位 | 关键设计 |
|---|---|---|
| `go-crud` | **独立多后端 DAL 库** | 8 种引擎各为子 module；泛型 `Repository[DTO,ENTITY]` + `mapper.CopierMapper` 双向映射；统一的 Protobuf 分页/过滤契约 `pagination/v1`；内置缓存(Cache-Aside+SingleFlight)、审计(Auditor)、数据权限(Viewer 五级范围) |
| `onexstack/pkg/store` | **应用内 GORM-only 封装** | 泛型 `Store[T]` + `DBProvider` 接口（注入 `*gorm.DB`）+ `where.Where` 条件构造器（函数式 Option）+ 全局 `Registry`（AutoMigrate）+ `Logger` 接口 |

**核心差异**：go-crud 是"自带实现的多引擎库"，onexstack/store 是"单一 GORM 的轻封装"。
bald 二者都不直接照搬：

- bald 是**框架**，不是 DAL 库。若把 8 种引擎实现塞进核心，违反 P5（零后端耦合）——
  与 bald 在 `registry`/`config` 上「核心只定接口、实现由调用方桥接」的做法自相矛盾。
- 但 bald 比 onexstack/store 多一层需求：**存储引擎应可替换**（演示/测试用内存，生产用 GORM/Mongo）。

**结论**：bald 的存储层 = go-crud 的「**契约 + proto 标准化**」+ onexstack 的「**泛型封装 + 注入接口**」，
但**具体引擎实现留在独立子模块**，通过桥接接入，核心只提供抽象与可选默认实现。

---

## 2. 分层架构

```
pkg/store                  ← 核心（零后端耦合）：抽象 + 契约 + 可选内存实现
 ├─ store.go                Store[T] 泛型 CRUD（依赖 DBProvider 接口）
 ├─ provider.go             DBProvider 接口（注入具体 DB 句柄）
 ├─ where.go                Query 条件构造（与引擎无关，DTO 字段级）
 ├─ logger.go               Logger 接口（对齐 pkg/log）
 └─ inmemory/              ← 内置内存实现（e2e/演示零依赖，类比 registry/inmemory）
pkg/store/contract/        ← Protobuf 契约（分页/过滤/排序，单一真相源）
     pagination/v1/         （借鉴 go-crud pagination/v1，buf 生成）

bald-store-gorm/           ← 独立子模块（可选，业务按需 go get）
bald-store-mongo/          ← 独立子模块（可选）
```

> 与 bald 现有范式一致：`pkg/store` 只定义 `Store[T]`/`DBProvider`/`Where`，
> GORM/Mongo 实现是独立 module，经构造参数注入 `DBProvider`，核心 go.mod 不引入 gorm/mongo。

## 3. 核心契约（核心包，零引擎依赖）

### 3.1 `DBProvider` — 引擎句柄注入点（依赖倒置）

```go
// DBProvider 提供数据库句柄；具体引擎由调用方实现并注入。
type DBProvider[T any] interface {
    // DB 返回当前上下文下的存储句柄（*gorm.DB / *mongo.Collection / 内存 map 等）。
    DB(ctx context.Context) (Queryable[T], error)
}
```

> 参照 onexstack `store.DBProvider`，但把 `*gorm.DB` 抽象为 `Queryable[T]` 接口，
> 使内存/SQL/NoSQL 共用同一 Store 泛型逻辑。

### 3.2 `Store[T]` — 泛型 CRUD（引擎无关）

```go
type Store[T any] struct {
    provider DBProvider[T]
    logger   Logger
    mapper   Mapper[T, EntityOf[T]] // 可选 DTO↔Entity 映射
}

func NewStore[T any](provider DBProvider[T], opts ...Option[T]) *Store[T]

// 基础 CRUD（签名对齐 onexstack Store）
func (s *Store[T]) Create(ctx, obj *T) error
func (s *Store[T]) Update(ctx, obj *T) error
func (s *Store[T]) Delete(ctx, opts *Where) error
func (s *Store[T]) Get(ctx, opts *Where) (*T, error)
func (s *Store[T]) List(ctx, opts *Where) (count int64, ret []*T, err error)
// 扩展（对齐 go-crud 能力，按需）
func (s *Store[T]) ListWithPaging(ctx, req *paginationv1.PagingRequest) (*PagingResult[T], error)
func (s *Store[T]) Count(ctx, opts *Where) (int64, error)
func (s *Store[T]) BatchCreate(ctx, objs []*T) error
func (s *Store[T]) Upsert(ctx, obj *T) error
```

### 3.3 `Where` — 引擎无关查询条件

```go
// Where 以 DTO 字段名表达条件，由具体引擎翻译成 SQL/NoSQL。
type Where struct {
    Offset  int
    Limit   int
    Filters map[string]any        // 字段=值（精确）
    Queries []Query               // 结构化条件（见 contract/pagination FilterExpr）
}
func (w *Where) Apply(q Queryable[T]) Queryable[T] // 引擎实现
```

> onexstack 的 `where.Options` 直接绑定 `*gorm.DB`，此处解耦为接口方法 `Apply`，
> 让内存/Mongo/GORM 各实现自己的翻译，核心 Store 不感知引擎。

### 3.4 `Logger` — 对齐 `pkg/log`

```go
type Logger interface {
    Error(ctx context.Context, err error, msg string, kvs ...any)
}
```

## 4. Protobuf 契约（分页/过滤/排序）

直接复用 go-crud 的 `pagination/v1`（已含 `PagingRequest` / `FilterExpr` / `Operator` 29+ 操作符 /
`Sorting` / `FieldMask`），避免重复造轮子。需要时在 `bald/api/proto/bald/store/v1/` 下放一份等价定义，
或用 `buf` managed mode 引用 go-crud 的 proto 模块。

- `PagingRequest`：`Page`/`PageSize`/`Offset`/`Limit` + `FilteringType`(`FilterExpr`/`Query`/`OrQuery`) + `OrderBy`
- `PagingResult[T]`：`Items []*T` + `Total uint64` + `NextToken`（Token 分页）
- 三种分页策略：Page / Offset / Token（无限滚动），对齐 go-crud 的 `paginator` 三实现

> 契约优先：DTO 的列表请求/响应用 proto 生成，与 gRPC/HTTP 共享同一类型（bald 全栈 proto 化主线）。

---

## 5. DTO ↔ Entity 映射

- 参考 go-crud 的 `mapper.CopierMapper[DTO, ENTITY]`：API 层用 DTO（proto 生成），存储层用 Entity（表/文档结构）。
- bald 的 `Store[T]` 默认 `T = DTO`；若需分离 Entity，通过 `Option` 注入 `Mapper`，
  `Create/Get/List` 内部自动 `DTO→Entity→DB→Entity→DTO`。
- 内存实现（`inmemory`）直接用 `T`（map[string]*T），无需 mapper，零依赖。

## 6. 与现有桥接范式对齐

| 能力 | 抽象（核心） | 实现（独立子模块） |
|---|---|---|
| 注册中心 | `registry.Registrar` | `registry.FromKratos` |
| 配置中心 | `config.RemoteSource` | `config.FromKratosSource` |
| 数据存储 | `store.Store[T]` + `DBProvider[T]` | `bald-store-gorm`（`NewGormProvider(db)`）/ `bald-store-mongo` |

业务接线示例（类比 `appkit`）：

```go
db, _ := gorm.Open(...)                       // 或 mongo.Connect(...)
provider := baldgorm.NewGormProvider[User](db) // 桥接：*gorm.DB → DBProvider[User]
repo := store.NewStore[User](provider, store.WithLogger(log.FromContext(ctx)))
```

## 7. 不借鉴的部分（代价与风险）

| 参考项 | 是否纳入 | 理由 |
|---|---|---|
| go-crud 8 引擎内置实现 | ❌ | 违反零耦合，且维护成本高；改为独立子模块按需引入 |
| go-crud Redis 缓存层 | ⚠️ 可选 | 缓存属横切关注点，建议放 `bald-store-gorm` 子模块（Cache-Aside+SingleFlight），核心不绑 Redis |
| go-crud Viewer 数据权限（五级范围） | ⚠️ 可选 | 与 `contextx` 用户上下文结合，作 `Where.Apply` 的前置注入，业务侧实现 |
| go-crud Auditor 审计 | ⚠️ 可选 | 与 `pkg/log` + `contextx` 结合，作 Store 钩子，不进核心 |
| onexstack 全局 `Registry`(AutoMigrate) | ⚠️ 微调 | 全局单例易与多租户冲突；bald 用显式 `provider.Migrate(models...)` 替代 |

## 8. 落地步骤与进度

### 8.1 已落地（核心骨架，零引擎依赖）

- **Proto 契约**：`api/proto/bald/store/v1/store.proto` → 生成至
  `pkg/conf/gen/go/bald/store/v1`（含 `PagingRequest` / `PaginationResponseMeta` /
  `FilterExpr` / `FilterCondition` / `Sorting` / `Operator` / `Direction`）。
  精简自 go-crud `pagination/v1`（去掉 gnostic OpenAPI 注解），仅依赖 protobuf WKT，可离线 `buf generate`。
- **核心抽象** `pkg/store`：
  - `store.go`：`Store[T]`（泛型 CRUD 门面）+ `DBProvider[T]`（句柄注入）+ `Queryable[T]`（后端实现契约）
    + `ListWithPaging`（`PagingRequest` → `Where` 翻译：页码/偏移/令牌三种分页 + 过滤 + 排序 + `PaginationResponseMeta` 回填）。
  - `where.go`：`Where` 引擎无关条件 + 便捷构造 `Eq/Gt/Gte/Lt/Lte/In/Nin/Like/Contains/Sort/SortDesc`。
  - `logger.go`：`Logger` 接口（最小子集，避免反向依赖 `pkg/log`）+ `NopLogger` + `FromLogger` 适配器。
  - `errors.go`：哨兵错误 `ErrNotFound` / `ErrConflict` / `ErrInvalidToken`。
- **内存实现** `pkg/store/inmemory`：`Provider[T]`（map + RWMutex）+ 反射字段提取的过滤/排序/分页，
  零外部依赖，供 e2e/单测/原型使用。`NewProvider[T](keyOf)` 注入主键提取函数。
- **测试**：`pkg/store/inmemory/inmemory_test.go` 冒烟测试（CRUD + 冲突 + 过滤 + 排序 + 分页），
  `go test ./pkg/store/...` 通过，**长期保留**作为回归。

### 8.2 已落地（桥接子模块 + 示例，由业务侧按需引入）

3. **桥接子模块 `bald-store-gorm`**（独立 go.mod，已落地）：
   - `gorm.go`：`Provider[T]`（持有 `*gorm.DB` + `keyOf`）+ `gormQuery[T]` 实现 `Queryable[T]`。
   - `Where`→GORM 翻译：`applyFilter` 覆盖 `EQ/NEQ/GT/GTE/LT/LTE/LIKE/ILIKE/NOT_LIKE/IN/NIN/IS_NULL/IS_NOT_NULL/CONTAINS/STARTS_WITH/ENDS_WITH/BETWEEN`；`applySorting` 翻译 `ASC/DESC`；`applyPaging` 翻译 `Offset/Limit`。
   - 字段名默认 snake_case 翻译（`toColumn`）；若要精确列名，`Where.Filter` 直接传数据库列名即可。
   - `NewGormProvider[T](db *gorm.DB, keyOf)` 注入；`Migrate(ctx, models...)` 委托 GORM `AutoMigrate`。
   - 唯一约束冲突识别为 `store.ErrConflict`；记录缺失识别为 `store.ErrNotFound`。
   - 测试 `gorm_test.go`（SQLite 内存库，CRUD + 冲突 + 过滤 + 排序 + 分页），`go test ./...` 通过，**长期保留**。
   - 同理可加 `bald-store-mongo`（实现 `DBProvider[T]` + `Queryable[T]` 即可，业务代码零改动）。
4. **示例 `_example/bald user`**（已落地）：演示内存 ↔ GORM 切换，build tag 隔离后端依赖。
   - 业务代码 `user/entity.go`（`runDemo`）完全不感知后端；具体 Provider 由 `buildProvider()` 提供，
     两个实现用 build tag 隔离：
     - `user/provider_mem.go`（`//go:build !gorm`）→ `inmemory.NewProvider[User]`（默认构建，零外部依赖）。
     - `user/provider_gorm.go`（`//go:build gorm`）→ `baldgorm.NewGormProvider[User]`（SQLite，需 `-tags gorm`）。
   - 运行：
     ```bash
     cd _example && go run ./bald user              # 内存版
     cd _example && go run -tags gorm ./bald user   # GORM+SQLite 版
     ```
   - `_example/go.mod` 已加 `require github.com/kalandramo/bald-store-gorm` + `replace => ../../bald-store-gorm`；
     因 `_example` 不被主模块 `go build ./...` 扫描，默认主模块零 GORM 依赖。

> 已落地部分不引入任何引擎依赖，符合 P5；第 3 步起的桥接子模块由业务侧 `go get` 引入。

## 9. 接入示例（核心骨架用法）

```go
import (
    "github.com/kalandramo/bald/pkg/store"
    "github.com/kalandramo/bald/pkg/store/inmemory"
    storev1 "github.com/kalandramo/bald/pkg/conf/gen/go/bald/store/v1"
)

type User struct {
    ID   string
    Name string
    Age  int
}

// 1) 选后端：内存（演示）或 bald-store-gorm 的 GormProvider（生产）。
provider := inmemory.NewProvider[User](func(u *User) string { return u.ID })

// 2) 构造 Store（可注入 pkg/log 适配器）。
repo := store.NewStore[User](provider, store.WithLogger(store.FromLogger(logger)))

// 3) CRUD / 分页。
_ = repo.Create(ctx, &User{ID: "1", Name: "alice", Age: 30})
res, _ := repo.ListWithPaging(ctx, &storev1.PagingRequest{
    Page:    proto.Uint32(1),
    Sorting: []*storev1.Sorting{store.SortDesc("age")},
    FilterExpr: &storev1.FilterExpr{
        Type: storev1.FilterExpr_AND,
        Conditions: []*storev1.FilterCondition{store.Gt("age", "18")},
    },
})
// res.Items []*User；res.Meta 含 total / current_page / page_size / total_pages。
```
