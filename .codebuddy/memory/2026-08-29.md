### 实施中踩到并修复的坑（重要，复用时可直接规避）

1. **`protojson.Unmarshal` 是替换语义**，会重置整个 message，清掉 `NewBootstrap()` 的默认值。解法：先解析到 `msg.ProtoReflect().New()` 空消息，再 `proto.Merge`。
2. **`proto.Merge` 对 repeated 字段是 append 而非替换**：默认值 `["stdout"]` + 配置 `["stdout"]` = 两个 stdout，表现为**日志向 stdout 写两遍**（冒烟时才暴露）。解法：新增 `clearPresentLists(dst, src)`，合并前把「src 中 Has==true 的 list 字段」在 dst 侧 Clear；嵌套 message 递归。
3. **Duration 不能用 `time.Duration.String()`**：90s → `"1m30s"`，而 protojson 的 Duration 只接受以 `s` 结尾的十进制秒数。必须 `strconv.FormatFloat(d.Seconds(),'f',-1,64)+"s"` → `"90s"`。
4. **env/flag 值类型与 proto 不匹配**：`protojson` 严格模式不接受 `"8080"`→int32、`"true"`→bool。已实现 `coerceScalar` 按字段描述符做类型规范化（含 enum 值名/编号、纳秒整数→Duration）。
5. **顺带发现两个既有静默缺陷**（均与 mapstructure 字符串匹配有关）：
   - 配置文件 `http.tls.*` 段被忽略：`SecureServingOptions` 用 `mapstructure:",squash"` 内嵌 `TLSOptions`，viper 实际期望 `http.enabled`。proto 契约确立 `http.tls.*` 为正确键路径。
   - `--log.*` 实际不生效：`logOpts.AddFlags(pflag.CommandLine)` 注册后从未 `Parse`。改由 `appkit.Bind("", logOpts)` 接入统一解析，Logger 改为两阶段初始化（默认 → BeforeStart 按配置重建）。

### 竞态修复（同日追加，`go test -race ./...` 现为零报告）

`pkg/server` 两组竞争 + `pkg/appkit` 一组，均已修复：

1. **`GRPCServer.ln` / `HTTPServer.ln` 字段**：`Start`（errgroup goroutine）写 vs `Endpoint()`（appkit 主 goroutine，waitForEndpoints 以 10ms 轮询）读。
   - 解法：`sync.RWMutex`（读多写少：Start 写一次之后只读）。
   - **关键坑**：`Endpoint()` 必须先取快照再解锁，**不能持锁调用 `Extract()`** —— 后者内部枚举网卡（`net.Interfaces()`），是耗时系统调用，持锁会阻塞 Start 写入。
2. **`ln` 指向的 listener 内部状态**：`listen()` 构造 vs `ln.Addr()` 读。这是 #1 的连带（`s.ln` 无同步时，读到的指针虽非 nil 但对象内部写入不可见）；加 mutex 后一并消失（锁提供 happens-before）。
3. **`GRPCServer.readinessCancel`**：`Start` 写 vs `Stop` 读。同一把锁覆盖。
4. **`appkit.Run` 的 loadConfig 顺序**（这个是主要的）：原实现把 loadConfig 放在防重入 CAS **之前**，导致并发 Run 同时执行 loadConfig，并发写 `a.cfg.cfgFile`（pflag 绑定其地址）与 `a.cfg.v`。
   - 解法：**CAS 在前、loadConfig 在后**，用「显式归还 running + 不注册 defer close」等价保住原语义（配置失败不占 running/done、不 double close done）。
   - 注意两个 defer 必须在 loadConfig **成功之后**注册，否则失败路径会 close done。
5. **测试自身的竞态**：`TestRun_NoReentrant` 用共享变量 `secondErr` + 轮询读取，无同步。改为 channel 传递。
6. **顺带修复 goroutine 泄漏**：`GRPCServer.Start` 原本先启动 readiness 轮询 goroutine 再 listen，listen 失败时该 goroutine 无人取消。改为 listen 成功后再启动。

新增回归测试：`pkg/server/server_test.go`（Start/Endpoint/Stop 三者并发、Stop 与 Start 重叠、listen 失败不泄漏 goroutine）、`pkg/appkit/appkit_test.go`（配置失败可回收重入槽、4 路并发 Run 恰好 1 成功 + 3 ErrAlreadyRunning）。

**踩坑记录**：写并发测试时，成功进入运行态的 Run 会阻塞在 mock 的 `startBlock` 上，必须先收齐 N-1 个 ErrAlreadyRunning 再 cancel，否则死锁。另外 gRPC 在 Serve 之前被 GracefulStop 会返回 `grpc.ErrServerStopped`，这是正常语义，断言需放行。

### protovalidate Go 运行时接入 + e2e 回归测试建立（当日）

### grpc-gateway 挂载收尾 + 回归 e2e 时再暴露并修复 3 个真实框架 bug（当日续）

**背景**：grpc-gateway 此前只跑过手动冒烟，未接 e2e。本次把 REST 用例写进 `greet_e2e_test.go`
（`TestGreet_REST_SharesSameRules`，证明 REST 与 gRPC 共用 proto 注解 + 手写校验器），
`-race` 全量跑通后暴露了 3 个此前从未触发的真实缺陷。

**Bug1：`config.Load` 的 `BindPFlags` 把零值 flag 压过 env/文件**
- 现象：e2e 用 `t.Setenv("BALD_DEMO_GRPC_ADDR", 随机端口)` 覆盖配置文件 `:9090` 完全失效，
  grpc 仍监听 `:9090`。根因 viper 语义 flag > env > 文件，`BindPFlags` 把未传 flag 的零值
  写进 override 层。
- 修复：`bindViperBasics` 改为仅对 `flags.Changed == true` 的 flag 调 `BindPFlag`；
  语义变为「flag 被显式设置才覆盖 env/文件」。`pkg/config` 测试全绿无回归。

**Bug2：`GRPCServer` 缓存 `addr` 快照与 `cfg` 指针不同步**
- 现象：env 覆盖后 HTTP server 监听正确、gRPC server 仍监听默认值，`Endpoint()` 返回旧地址。
- 根因：`NewGRPCServerWithRegister` 构造时 `addr: cfg.GetAddr()` 存字段，而
  `appkit.BeforeStart` 的 `Unmarshal` 在**构造之后**才把覆盖地址写回同指针 `bootstrap.GetGrpc()`。
- 修复：删除 `addr` 字段，`Start`/`Endpoint` 实时读 `s.cfg.GetAddr()`。

**Bug3：`GatewayServer` 构造期固化后端地址 + Start/Stop 死锁**
- 现象1：网关在构造时 `grpc.NewClient(backendAddr)`，env 覆盖无效 → 永远连 `:9090`。
- 现象2：gateway 的 `Start` 在持 `mu` 锁期间进入阻塞 `Serve`，`Stop`（`mu.Lock()` 才能 `Shutdown`）
  与之死锁 → `app did not stop within timeout`。
- 修复：
  ① `NewGatewayServer` 改收 `*confv1.Grpc` 指针（不再接受固化字符串），
     `conn` 与 handler 构建**延迟到 `Start`**，实时读 `backend.GetAddr()`（env/flag 生效）；
  ② `Start` 仅在建立 conn/register/attach 阶段持锁，attach 完**立即释放锁**再进 `Serve`；
  ③ 构造期传 `nil` handler（不挂 `/`），`Start` 里 `HTTPServer.attachHandler(h)` 延迟挂载，
     保留 `/healthz` `/readyz` 探针。
- e2e 端口分配改为 `freeAddr(t)`（`net.Listen("tcp","127.0.0.1:0")` 取真实端口后关掉）：
  gateway 后端必须是**可连接地址**，**不能用 `:0`**（转发时无从得知真实端口）。
  同步更新 `pkg/server/server_test.go`（两处 gateway 测试改 `freeAddr` + `*confv1.Grpc` 指针）、
  路线图与 grpc-gateway 文档示例。

全 PASS，无数据竞争**。`make verify`（核心 build+test + example build+vet）exit=0。
