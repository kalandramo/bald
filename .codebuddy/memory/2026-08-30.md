## 代码审查后全量修复（P0-P4 复查发现的 6 项问题）

用户 "@command://cr 审查代码变更" 后要求"全修"。修复全部落地并验证全绿：

1. **🔴 flatten 丢弃 OR 语义**：`pkg/store/store.go` 原 `flatten` 静默把 `FilterExpr.Groups` 展平为 AND（丢失 `FilterExpr.Type` AND/OR）。改为报错（后端仅支持 AND 扁平）；proto 实际结构是 `FilterExpr.Type`(AND/OR)+`Groups []*FilterExpr`（非 `Logic` 字段，修正了初版误用 `GetLogic`/`FilterLogic_OR` 的编译错误）。补 `TestFlatten_RejectsOR`。
2. **🔴 NextToken 末页误发**：原 `translate` 无条件 `NextToken=encodeToken(off+ps)`，导致末页也返回 token、客户端空翻页。改为 `translate` 不预填，`fillTotal` 在 `total > offset+limit` 时才填 NextToken。补 `fillTotal` 末页判定测试。
3. **🟡 元数据字段类型统一**：`PageSize/NextToken/CurrentSize` 是原生指针，`Total/TotalPages/CurrentPage/CurrentOffset` 是 wrapperspb——保留 `uint32p`（原生）仅用于 PageSize，删误用。
4. **🟡 GORM ILIKE**：注释从不实"跨库可用 lower()"改为"仅字符串列安全 + 优先原生不区分大小写匹配 + lower() 兜底 SQLite"。
5. **🟡 codegen go_package**：`gen proto` 模板路径由 `.../codegen/{Name}/v1` 改为 `.../api/gen/go/bald/{Name}/v1`，与示例模块 + buf 生成目录对齐。
6. **🟡 gorm Update 零值/主键**：`Updates(obj)` 跳过零值且可能误改主键。改为 `Updates(toMapExcludeKey(obj))`（反射导出字段转 map、剔除主键列 `id`），写入零值且不动主键。
- **附带的 toColumn 真实 bug**：`"ID"`→`"i_d"` 导致 Update 报 `no such column: i_d`。修正 snake_case 算法（处理缩写：`ID`→`id`、`UserID`→`user_id`、`HTTPServer`→`http_server`）。此 bug 之前因 `Updates(obj)` 走模型自身列映射而未被暴露，改 map 更新后触发。

## M6.5 JWT 非对称（RS256/ES256）落地（从第二批提前，用户说"需要"即做）
Why：原 bald-authn-jwt 仅 HS256(对称)，签发/验签共用一密钥，下游持密钥即可伪造 token。非对称使签发方独占私钥、验证方只持公钥，是进多服务/企业 OIDC(JWKS) 门槛，也消除"密钥存进程内存"隐患。
How（只动 `bald/contrib/authn-jwt` 桥接子模块，核心 `pkg/authn` 零改动）：
- `jwt.go` 重构为 Option 构造：`WithHMACSecret`/`WithRSAKeys(priv,pub)`/`WithECDSAKeys(priv,pub)`/`WithSigningAlg`/`WithAllowedAlgs`/`WithIssuer`/`WithLeeway`；算法按密钥自动推断。验签 keyfunc 按 token alg 选公钥，拒 alg=none/密钥错位；`authn.AuthClaims` 经内部 `jwtClaims` 桥接 `jwt.RegisteredClaims` 互转（核心不 import jwt 库）。`Signer` 接口(`IssueToken`)供 biz 依赖；仅公钥方调 IssueToken 报错(无法伪造)。
- 范例 `bootstrap.InitBridges` 启动时 `authnjwt.GenerateRSA(2048)` 生成密钥对，构造 `Signer`(私钥,注入 auth biz Login)+ `Authenticator`(仅公钥,注入 gin/grpc 拦截器)两独立实例，演示签发/验签解耦；加**幂等保护**(避免重复生成密钥对破坏闭环——这是非对称下才暴露的 bug，HMAC 常量时隐而未现)。
- wire：`authbiz.New` 改收 `authnjwt.Signer`；`wire.go` 的 `provideSigner()` 返回 `bootstrappkg.Signer`（替换旧 `jwtSecret` 字符串别名），`wire_gen.go` 同步。
- 测试：`authn-jwt/jwt_test.go` 覆盖 RS256/ECDSA round-trip、`VerifyOnlyCannotSign`、`RSA_ForgedByOtherKeyRejected`；范例 `asymmetric_e2e_test.go` 验"私钥签→公钥验"闭环。go build/vet/test 全绿（example 18 用例 + authn-jwt）。
- 关键坑：原 `authn.AuthClaims` 无 `jwt.Claims` 接口（无 Valid()），必须桥接类型；`NewAuthenticator` 返回 `*Authenticator`（同时实现 authn.Authenticator 与 Signer），不能返回接口否则 IssueToken 不可见。`go mod tidy` 因 auth 包测试新增 authnjwt 直接依赖触发。
- 设计文档 M6.5 段 + §2.2「接」列表已更新；第二批剩余：外部 DB 真实切换(PG/MySQL)、gateway 生产化(yaml addr/TLS)。
- 生产姿态提示：范例用启动时生成密钥对（重启旧 token 失效），生产应从 KMS/固定 PEM 加载（私钥进 HSM、公钥可走 JWKS）。JWKS 端点为可选进阶未做。
